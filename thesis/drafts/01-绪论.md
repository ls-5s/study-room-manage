# 1  绪论

## 1.1 研究背景与研究意义

### 1.1.1 研究背景

自习室是高校学生开展自主学习和备考复习的主要场所。近年来高校在校生规模持续扩大，考研、考证与课程复习带来的自习需求在学期中后段集中释放，而自习室的座位数量由建筑空间决定，短期内难以同步增加。座位因此成为一种典型的稀缺空间资源：总量有限、使用时段集中、需求在考试周前后出现明显峰值。当供给与需求之间的缺口只能靠现场排队和先到先得来消化时，资源分配的公平性和使用效率都会下降。

传统自习室管理依赖现场占座与人工登记。学生到馆后自行寻找空位，部分座位被书本、水杯长期占用而实际无人使用；管理人员依靠巡查判断座位是否在用，遇到争议只能口头协调。这种方式的局限在三个方面比较突出。第一，座位状态不可见。学生在去自习室之前无法判断是否还有空位，只能到现场碰运气，来回寻找的时间成本由学生承担。第二，使用记录不可追溯。哪些座位在什么时段被谁使用，人工登记难以完整保留，出现纠纷时缺少依据。第三，管理动作滞后。占座行为往往在被发现时才处理，处理结果依赖管理人员的现场判断，标准不统一。

线上预约改变了这一状况，但也带来新的问题。预约把座位的使用权提前分配给具体的学生，使座位状态可以在查询阶段就被观察到，同时也让不到场的行为第一次变得可度量。问题在于，如果系统只提供预约入口而不对预约结果施加约束，预约就会退化为一种没有成本的占位手段：学生同时预约多个座位、预约后因故不到场、到场后不签到，都会让被预约的座位在整个时段内保持空闲，其他学生却无法使用。座位资源的浪费从线下的“占而不用”转移为线上的“约而不用”，问题的形式变了，实质没有变。

这一转变还有一层不易察觉的后果：约束缺失会把管理成本转嫁给守规则的学生。愿意到场的学生发现提前预约反而抢不到座位，逐渐放弃使用预约系统，回到现场碰运气；而习惯性失约的学生不受任何影响。系统使用率下降的同时，失约率上升，管理者对系统的信任也随之下降。这说明预约系统的成败不取决于预约功能本身，而取决于它能否让“约了就来”成为理性的选择。

高校图书馆空间服务的发展为这类问题提供了实践参照。冯兵等对高校图书馆空间预约服务进行了调查，讨论了预约服务的开展情况及相关问题<sup>[1]</sup>。座位预约需要同时处理身份、空间、时段与使用规则，不能仅依靠一个在线选座入口。对本项目而言，身份核验、时段划分与行为约束构成了预约管理的基本条件。与此同时，前后端分离的开发模式、成熟的 Web 框架与关系型数据库，使得一套面向单校区、功能适度、便于部署的预约系统可以在有限的开发周期内完成。

在此背景下，本文设计并实现一套校园自习室预约管理系统。系统的重点不在于把选座流程搬到线上，而在于围绕预约行为建立一套可执行的状态规则：预约必须签到，超时未签到记为失约，失约累计到阈值后限制预约，限制期满自动恢复。规则由服务端统一执行，前端只负责呈现，从而把“约了不来”的行为成本显性化。这一思路与既有座位预约系统的差别，构成了本文的出发点。

### 1.1.2 研究意义

从理论层面看，本文讨论的是稀缺空间资源在校园场景下的分配机制。预约制在会议室、场馆、实验设备等场景已有较多应用，其核心是把“先到先得”的排队规则替换为“按时段分配”的规则，从而提高资源的可计划性。但预约制要真正发挥作用，必须配套约束机制：没有约束的预约只是把排队转移到了另一个环节。本文将预约、签到、失约记录与限制期组织为一个可执行的状态机，说明约束机制如何与资源分配规则耦合，可为同类校园资源的预约系统设计提供参照。

从实践层面看，系统对三类主体都有直接价值。对学生而言，座位状态在预约前即可查询，选座从“到场寻找”变为“提前确定”，减少了无效往返；签到与取消规则明确了权利边界，预约后无法到场时可以提前取消，不必担心占用资源。对管理人员而言，自习室、时段与座位的维护集中在后台完成，预约记录与失约记录自动留存，处理占座举报时有据可查，巡查工作量随之下降。对学校而言，座位使用数据被结构化保存，分时段的预约量、签到率与利用率可以按日统计，为自习室的开放时段调整与座位扩容提供依据。

### 1.2 相关研究现状

### 1.2.1 国内座位管理系统的建设实践

国内高校的座位管理研究包含智能分配、在线预约与既有系统改造等方向。清华大学的智能座位管理系统把读者身份、座位分配与图书馆管理相结合，为座位管理信息化提供了较早的实践案例<sup>[2]</sup>。王彦等梳理了高校图书馆座位管理中预约系统的现状与实现问题，说明预约需要作为整体管理流程的一部分加以设计<sup>[3]</sup>。中国药科大学图书馆的在线预约系统则以具体高校为对象，介绍了座位预约系统的设计与实现<sup>[4]</sup>。张昕阳对图书馆自习区智能管理系统的升级改造进行了研究，反映出系统投入使用后仍需根据管理需求持续优化<sup>[5]</sup>。

围绕系统落地与使用过程，田元、马微讨论了图书馆座位管理系统的设计与实现，为同类管理系统的功能组织提供了案例<sup>[6]</sup>；徐海东等将位置服务用于座位管理，探索位置相关信息与座位服务的结合<sup>[7]</sup>。在使用行为方面，温红超以吉林大学鼎新图书馆为例，从经济学角度分析读者使用座位预约管理系统的行为，使研究视角由功能建设延伸到读者选择与资源使用<sup>[8]</sup>。张若友则讨论了高校图书馆座位预约系统的实施与存在问题<sup>[9]</sup>。这些研究提示，系统设计需要同时考虑功能可用性、读者使用方式与管理规则的执行条件。

技术实现上，不同研究根据应用条件选择了不同方案。林妍等设计了基于 GPS 定位的图书馆座位管理系统，将定位技术引入座位管理场景<sup>[10]</sup>；熊辉等采用 Python 实现图书馆自习室管理系统，提供了另一种软件实现路径<sup>[11]</sup>；卢春华等围绕高校图书馆选位系统展开设计，关注读者选位这一具体业务环节<sup>[12]</sup>。高许雷将物联网技术用于公共场所座位智能管理，研究对象进一步扩展到图书馆之外<sup>[13]</sup>。本文据此区分选座、预约与在场确认的职责，并结合项目条件采用二维码签到记录到场行为。

### 1.2.2 移动端预约与空间服务的发展

移动端服务使读者可以通过手机访问座位管理功能。王赛群等以湖南农业大学图书馆为例，讨论微信座位管理系统作用最大化的实现途径，关注既有平台在实际服务中的使用问题<sup>[14]</sup>。贺一轩、秦立静设计了基于微信小程序的图书馆座位预定系统，将小程序作为座位服务入口<sup>[15]</sup>。两类研究分别从服务运营与系统设计出发，为预约入口的组织提供了参照；具体采用微信平台还是浏览器，应结合身份认证方式、部署条件与维护成本决定。

预约对象也不限于单一座位。沈奎林等研究了研究小间预约系统的设计与实现，将独立学习空间纳入预约管理范围<sup>[16]</sup>；冯兵等关于高校图书馆空间预约服务的调查，则从更广的空间服务范围讨论了预约管理<sup>[1]</sup>。资源类型扩展后，系统需要明确预约对象、开放时段和使用条件。本文虽然以自习室座位为主要对象，仍将自习室、时段与座位分别建模，以便在资源调整时保持规则边界清晰。

资源分配与空间选择构成另一条研究线索。魏瑾瑞等研究自助选座系统资源分配效率的评价与优化，将关注点从预约功能延伸到资源分配效果<sup>[17]</sup>。国外研究中，Min 和 Lee 以数字阅览室中的个人学习为空间情境，结合个人空间与靠墙偏好讨论座位选择行为<sup>[21]</sup>；Cha 和 Kim 在同一图书馆情境下考察空间属性、空间选择行为与满意度之间的关系<sup>[22]</sup>。这些工作说明，座位并非只有“空闲”和“占用”两种管理属性，读者对空间的选择也值得考虑。本文据此保留按自习室和时段查看使用情况的统计维度，为后续分析资源使用差异提供数据基础。

### 1.2.3 现有研究的不足与本文的切入点

已有研究分别讨论了预约系统建设、读者使用行为、移动端服务与资源分配效率，为本文提供了设计参照。但不同系统的部署环境、资源类型和管理制度并不相同，不能仅凭功能描述判断其管理效果。本文将研究重点限定为本项目所需的预约流程与规则执行。

结合本项目的业务需求，需要重点处理三个环节。其一是状态记录，关联预约与签到，保留状态变化的时间线，便于核查是否到场及预约如何结束。其二是规则执行，将失约记录与后续预约资格连接，使限制条件能够由服务端统一判定。其三是历史稳定，在资源更名、停用或开放时段调整之后，仍保留原预约与统计所使用的资源信息。这些是本系统的工程要求，并不意味着既有研究均未涉及相应问题。

本文的切入点是将上述要求落实到同一业务流程：用状态机约束预约的生命周期并记录状态变化；用签到与失约记录判定到场情况，并把违约次数与预约资格绑定；用快照将历史统计与当前资源配置分开维护。本文通过具体实现与测试检验这些机制在本项目中的行为，不以此推断对所有高校场景的适用性。

### 1.3 论文主要研究内容与组织结构

本文围绕校园自习室预约管理系统开展设计与实现，主要工作包括四个方面。

第一，梳理业务规则并建立状态机。以学生、管理员两类角色为线索，明确预约、签到、取消、失约、完成五个状态之间的转换条件，把签到窗口、每日预约上限、失约阈值与限制期等规则写成可执行的判定逻辑，而不是停留在需求描述层面。

第二，设计数据模型与约束。围绕用户、自习室、时段、座位、预约、签到、违约、反馈与统计建立 14 张数据表，用生成列上的唯一索引保证同一座位在同一时段只能存在一条有效预约，用快照字段保证资源更名或停用后历史记录不发生漂移。

第三，完成前后端实现。前端基于 Vue 3 与 TypeScript 构建单页应用，按学生端与管理端划分路由；后端基于 Express 与 Sequelize 组织路由、控制器、服务与数据访问四层，把事务、加锁与状态转换集中在服务层，通过定时任务处理超时预约与到期预约。

第四，验证系统行为。以功能用例、规则边界用例与非功能检查三类测试覆盖主要业务流程，重点验证并发抢座、重复签到、跨日时区与停机恢复等容易出错的场景。

全文共七章。第 1 章说明研究背景、意义与现状；第 2 章介绍所用关键技术；第 3 章完成需求分析，给出功能需求、业务规则与非功能需求；第 4 章进行系统设计，包括总体结构、架构、数据库与接口设计；第 5 章按功能模块说明详细设计与实现；第 6 章说明测试方法与结果；第 7 章总结工作并讨论不足与改进方向。
