# 校园自习室预约管理系统的设计与实现

## 选题意义

自习室是高校学生完成课程学习、复习备考和开展自主学习的重要场所。对于依靠现场选座、物品占座和人工巡查的管理方式，学生通常需要到场后才能了解空座情况，管理人员也难以连续掌握座位的预约与使用过程。一些座位虽然被物品占用，但实际无人使用；一些学生提前预约后未能到场，却没有及时取消。座位信息与实际使用情况不一致，容易增加寻找空位的时间，也给日常管理带来困难。本课题据此选择校园自习室预约管理作为研究对象，尝试通过明确的业务规则和统一的信息系统改善上述流程。
对学生而言，系统的意义首先在于让座位信息能够提前查询。学生可以按日期、自习室和开放时段查看座位布局，区分空闲、已预约和维修停用等状态，再根据学习安排选择合适的位置。预约成功后，系统提供预约详情、签到时间和取消入口，使学生能够了解本人需要遵守的规则。无法按时到场时，提前取消可以让座位重新进入可预约范围。相比只提供预约按钮，将查询、确认、签到和记录查询连接起来，更有助于形成清楚、连贯的使用过程，减少因信息不明确造成的重复操作。
对管理人员而言，课题旨在把分散的资源维护与业务处理集中到后台。自习室名称、位置、座位布局和开放时段可以统一维护，预约记录也可按日期、房间和状态查询。面对学生咨询、占座反馈或签到异常，管理员能够结合预约时间、状态变化和处理日志核查原因，并记录处理结果。这样可以减少对口头说明和临时登记的依赖，也使人工核验、取消预约和违约撤销等操作具有可追溯的依据，便于后续检查。
课题还关注预约资格与实际使用之间的衔接。线上预约能够提前分配使用资格，但预约记录本身不能说明学生已经到场。通过签到、失约处理和操作留痕，可以明确预约后的使用要求，为核查到场情况和处理异常提供依据。违约限制使持续占用预约名额而不到场的行为受到约束，管理员核实和撤销的途径则为特殊情况保留处理空间。学生能够了解规则，管理员能够查阅处理依据，有助于使预约管理按照相同标准开展，减少规则不清引发的争议。
在资源使用分析方面，系统拟按日期、时段和自习室整理预约量、签到情况及相关使用指标。统计中分别记录预约数量、签到数量和按既定口径计算的使用指标，注明统计范围与计算方式。管理人员可以据此了解不同时间和空间的需求差异，作为调整开放安排、检查异常记录的参考。课题将首先验证统计数据与业务记录之间的一致性，实际管理效果仍需结合后续使用情况进行观察。
在软件工程实践方面，本课题具有较完整的业务链条，能够将需求分析、数据库设计、界面交互、接口开发与测试联系起来。并发抢座、重复提交、时间区间冲突和权限越界等问题，要求设计者把约束落实到服务端和数据库，而不能只依赖页面提示。围绕预约全过程开展分析和实现，有助于理解业务规则、数据一致性与操作记录之间的关系，形成可供同类资源预约业务参考的实现经验。
本课题限定在校园自习室的线上预约与日常管理，预期提交可运行系统、论文、测试记录和操作说明，并以流程完整性、数据一致性和异常处理能力检验成果。

## 国内外研究现状概述

国内高校图书馆座位管理研究涉及空间预约服务、系统设计、读者行为和资源分配等多个方面。冯兵等通过高校图书馆空间预约服务调查，讨论相关服务的开展情况和问题，为认识预约业务所处的管理环境提供了参考。这类研究为梳理空间预约服务中的身份、开放时间、使用条件和管理制度提供了参考，有助于从整体服务流程理解预约需求。
在系统建设方面，陈武等介绍清华大学智能座位管理系统的设计与实现；王彦等讨论高校图书馆座位管理中预约系统的现状与实现；王孝亮等以中国药科大学图书馆为例研究座位在线预约。上述研究为读者身份、座位资源与预约记录之间的关系提供了案例。张昕阳讨论自习区智能管理系统的升级改造，田元、马微研究座位管理系统的设计与实现，也体现出系统建设与后续维护需要结合具体业务条件持续调整。
在位置服务与现场信息采集方面，徐海东等将位置服务引入座位管理，林妍等探索基于GPS定位的实现方案，高许雷讨论物联网条件下的公共场所座位管理。这些技术路径为在场信息采集提供了参考，但软硬件投入、定位条件和维护要求存在差异。位置服务和物联网方案扩展了座位状态核验的技术选择，也使系统建设需要结合设备条件与信息采集方式，区分预约记录、签到记录和实际使用情况。
在读者使用与服务实施方面，温红超以吉林大学鼎新图书馆为例，从经济学角度分析座位预约系统的使用行为；张若友讨论系统实施及存在的问题。这些工作提醒设计者关注预约后的实际使用与规则执行，而不能只考虑预约是否成功。魏瑾瑞等研究自助选座系统资源分配效率的评价与优化，进一步将关注点延伸至分配效果。这些工作分别涉及系统实施、读者使用行为与资源分配效率，为本课题提供了不同角度的参考。
实现方式和服务入口也呈现出不同选择。熊辉等采用Python构建图书馆自习室管理系统，卢春华等研究高校图书馆选位系统；王赛群等讨论微信座位管理系统在服务中的作用，贺一轩、秦立静设计基于微信小程序的座位预定系统。沈奎林等的研究小间预约系统则将预约对象扩展到独立学习空间。这些案例为功能划分提供参照，也说明技术选型需要服从访问入口、资源类型和部署条件。
国外相关研究还关注学习空间本身与读者选择的关系。Min和Lee研究数字阅览室中个人学习的空间选择行为；Cha和Kim考察高校图书馆空间属性、空间选择行为与满意度的关系。这类研究提示，座位使用差异不能仅用空闲和占用概括，还需要保留空间和时段维度。空间选择研究为理解座位需求差异提供了参照，按空间与时段组织预约、签到等记录，可以为后续比较资源使用情况保留数据基础。
综合已有材料，本课题将研究重点放在预约全流程及规则的一致执行。借鉴相关系统的功能组织，采用前后端分离方式实现选座、预约、签到、取消、失约处理和反馈管理，通过事务、唯一约束及状态日志处理冲突与追溯问题。本课题将结合校园管理条件，通过可复现的功能与边界测试检验具体实现，实际使用效果需进一步验证。

## 主要研究内容

本课题围绕校园自习室预约管理开展需求分析、架构设计、功能开发和测试验证。系统面向学生、管理员和超级管理员三类角色，主要业务覆盖资源查询、选座预约、签到、取消、失约处理、反馈和统计。系统以完整业务流程为依据，明确操作条件、结果和异常处理方式，保持需求、数据、接口与页面之间的一致。
首先，完成需求分析和业务建模。梳理学生查询空座、选择日期时段、确认预约和到场签到的过程，以及管理员配置资源、核验异常、处理反馈和查看统计的过程。明确各角色能够访问的数据范围，区分学生查看本人记录与管理员查看全量记录的权限。围绕预约建立状态转换关系，规定待签到、已签到、已完成、已取消和已失约的含义，并明确每日预约上限、签到窗口、取消条件和限制期限等业务规则，区分可配置参数与固定判定条件。
其次，设计总体架构和数据模型。系统采用前后端分离架构，前端承担界面展示与交互，后端负责权限校验、业务处理和数据访问。数据库围绕用户、自习室、开放时段、座位、预约、签到、违约、反馈及统计等实体建立关联，明确主键、外键、索引与约束。预约记录保存资源名称、位置和座位编号快照，使资源改名或调整后仍能理解历史记录；状态日志与操作审计分别记录业务变化和重要管理动作，为查询与核查提供依据。
第三，实现资源展示与学生端功能。提供注册登录、资料维护和密码修改等基础入口，支持自习室列表、位置说明、开放时段及座位平面图展示。学生可以按日期和时段查看座位状态，在确认预约信息后提交申请，并查询预约详情、签到要求与状态变化。系统支持规定条件下取消预约，提供二维码签到、本人违约记录查询及反馈提交功能。页面需要对已经开始的时段、维修座位和预约冲突给出清楚提示，并在提交前与服务端再次核验。
第四，研究预约创建和状态处理中的一致性问题。创建预约时校验用户是否受限、资源是否开放、时段是否有效，以及同一学生和座位是否存在时间重叠。在事务内组织校验与写入，结合数据库唯一约束处理并发抢座，使用幂等键避免重复提交产生多条预约。签到需要检查资源归属、预约状态和时间窗口，重复签到不能重复生成记录。通过定时任务处理超时未签到和使用到期，确保预约、签到、违约和状态日志之间保持一致。
第五，实现管理业务与辅助功能。管理员可以维护自习室、开放时段和座位，按条件查询预约，并对符合条件的预约进行人工核验或取消。违约模块支持规则配置、有效记录查询及有原因的撤销处理；反馈模块记录占座、设备和环境等问题，按照受理、处理和结束的过程保留结果。统计模块按日期、自习室和时段展示预约与签到情况，并提供报表导出。系统同时完善统一错误响应、表单校验、异常提示和必要的操作留痕。
最后，开展系统测试并整理成果。测试覆盖正常流程、输入边界、权限隔离、并发冲突、重复提交及时间状态转换，核对接口响应与数据库记录是否一致。对缺陷保留触发条件、修复过程与回归结果，区别功能验证和真实使用效果评估。完成后提交可运行系统、部署与操作说明、测试材料和毕业设计论文，使文字、图表、界面截图和代码行为能够相互对应，并明确当前实现尚未覆盖的应用条件。

## 拟采用的研究思路（方法、技术路线、可行性论证等）

本课题拟采用文献分析、业务建模、原型设计、分模块开发和测试验证相结合的研究思路。首先阅读任务书及座位预约相关材料，从资源信息不可提前查询、预约冲突和约后未到等场景提炼问题，区分学生与管理员的操作目标。以用例和流程图描述主要业务，再将需求转化为可检查的规则，例如允许预约的日期范围、取消条件、签到时间和状态转换要求。需求以项目材料及可复现的业务场景为依据，修改规则时同步检查界面、接口和数据设计。
总体采用B/S架构，用户通过浏览器访问，前后端通过HTTP接口交换数据。前端使用Vue 3、TypeScript和Vite，结合Vue Router组织页面、Pinia维护登录及业务状态，使用Element Plus构建表单和管理界面，Axios负责请求，ECharts展示统计数据。张志鹏等关于Vue.js业务系统的应用案例，可为页面与数据交互组织提供参考。前端负责清楚呈现状态与操作结果，服务端保留对权限、时间和资源可用性的最终判断，避免绕过页面后产生无效数据。
后端采用Node.js、Express和TypeScript，按路由、控制器、业务服务和数据模型划分职责，通过Sequelize访问MySQL。身份认证使用JWT，密码采用哈希方式存储，并按角色和资源归属限制访问。数据模型分别描述用户、资源和业务记录，通过迁移维护表结构，为高频查询和关键冲突条件配置索引。对错误进行统一处理，向页面返回可以理解的提示，并避免在普通响应中暴露数据库语句等内部信息。
核心业务按预约状态机设计，逐项规定状态转换的触发者、时间条件和关联记录。创建预约时，在事务中核查用户资格、自习室及座位状态、时段有效性和时间重叠，并在加锁后重新检查关键条件。应用层校验用于返回明确原因，数据库唯一约束作为并发写入的保障；幂等键用于识别同一请求的重复提交。预约写入与初始状态日志放在同一事务中，减少主记录成功而日志缺失等不一致情况，并针对抢座和重复请求单独验证。
签到由服务端核验预约归属、自习室信息、状态和签到窗口，二维码作为信息载体辅助核验，不将其等同于持续在场检测。定时任务按运行情况分别处理超时未签到、异常停机补偿和已签到到期，状态更新需检查原状态，并与关联日志保持一致；预约资格根据限制截止时间校验，到期后恢复。对于违约撤销、人工签到和取消预约等管理操作，保留操作人、原因与处理时间。资源名称变化后，通过预约快照保留历史信息，避免查询结果随当前配置发生含义变化。
开发过程先完成登录、资源查询、预约与签到主流程，再接入违约、反馈和统计。测试用例组织参考章晓芳等关于用例集约简的研究，以及杨劲涛、郭荷清关于黑盒测试用例的研究，结合等价类、边界值和状态迁移方法，检查非法输入、相邻与重叠时段、重复提交、越权访问以及定时转换。发现问题后记录条件并补充回归用例，同时核对页面提示、接口响应与数据库状态。统计部分单独明确预约量、签到率和使用指标的口径，避免混用不同含义的数据。
可行性方面，所选框架与数据库能够支持课题所需的Web交互、事务及定时处理，项目现有代码、模块文档和测试材料可用于复核方案。研究范围限定为单校校园场景，不依赖专用感知设备；主要难点集中在并发一致性、时间边界和异常恢复，拟通过服务端统一判定、事务约束及专项测试处理。成果评价以功能与规则验证为主，真实管理效果留待实际使用进一步检验。
