# 认证与用户模块开发文档

> 模块编号：M01  
> 文档版本：V1.1  
> 依赖：[公共约定](./README.md)、[系统基础与运维](./07-系统基础与运维模块.md)  
> 当前状态：设计完成，待实现

## 1. 模块目标

认证与用户模块负责学生注册、登录、退出、会话校验、个人资料和角色权限。它不是单纯的登录页，而是其他所有业务模块的用户和权限基础。

完成本模块后，系统应能可靠回答以下问题：

- 当前请求来自哪个用户。
- 当前用户是学生还是管理员。
- 当前账号是否可用、是否处于违约限制期。
- 当前用户是否能访问某条预约或反馈记录。

第一版不支持管理员自助注册、短信验证码、第三方登录和找回密码。管理员账号由受控初始化脚本创建。

## 2. 功能范围

| 功能 | 学生 | 管理员 | 说明 |
| --- | --- | --- | --- |
| 注册 | 允许 | 禁止 | 只能创建 `student` 角色 |
| 登录 | 允许 | 允许 | 登录后签发 Access Token |
| 退出 | 允许 | 允许 | 撤销当前会话 |
| 查询当前用户 | 允许 | 允许 | 返回脱敏后的用户信息 |
| 修改资料 | 允许 | 允许 | 昵称、邮箱、手机号、头像地址 |
| 修改密码 | 允许 | 允许 | 必须验证旧密码 |
| 查看本人违约 | 允许 | 不支持 | 管理员通过违约模块查询 |
| 停用用户 | 禁止 | 允许 | 保留历史记录和审计 |

## 4. 数据设计

### 4.1 `users`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键、自增 | 用户 ID |
| `student_no` | VARCHAR(32) | 非空、唯一 | 学号；管理员可使用固定内部编号 |
| `username` | VARCHAR(64) | 非空、唯一 | 登录账号 |
| `display_name` | VARCHAR(64) | 非空 | 展示名称 |
| `email` | VARCHAR(128) | 可空、唯一 | 注册时可选 |
| `phone` | VARCHAR(20) | 可空 | 只保存规范化后的号码 |
| `avatar_url` | VARCHAR(512) | 可空 | 仅允许 http/https 地址 |
| `password_hash` | VARCHAR(100) | 非空 | bcrypt 哈希 |
| `role` | ENUM | 非空 | `student`、`admin` |
| `status` | ENUM | 非空 | `active`、`disabled` |
| `violation_count` | INT UNSIGNED | 默认 0 | 当前有效违约数 |
| `restriction_started_at` | DATETIME | 可空 | 当前预约限制开始时间 |
| `restriction_until` | DATETIME | 可空 | 预约限制截止时间 |
| `last_login_at` | DATETIME | 可空 | 最近成功登录时间 |
| `created_at` | DATETIME | 非空 | 创建时间 |
| `updated_at` | DATETIME | 非空 | 更新时间 |

唯一字段比较使用数据库默认排序规则时，应在迁移中明确大小写策略。登录账号建议统一去首尾空格并做大小写不敏感比较；学号按学校实际规则处理，默认区分全部字符。

### 4.2 `user_sessions`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | CHAR(36) | 主键 | 会话 ID，同时写入 JWT `sid` |
| `user_id` | BIGINT UNSIGNED | 外键 | 所属用户 |
| `jti` | CHAR(36) | 唯一 | Token 唯一标识 |
| `expires_at` | DATETIME | 非空 | 会话绝对过期时间 |
| `revoked_at` | DATETIME | 可空 | 退出或管理员停用时间 |
| `created_at` | DATETIME | 非空 | 登录时间 |

使用会话表后，退出可以立即撤销服务端会话。认证中间件验证 JWT 后，再检查 `user_sessions` 和用户状态。第一版不实现 Refresh Token，Access Token 建议有效期 2 小时；刷新页面时由前端恢复同一会话。

### 4.3 索引

- `users.student_no`、`users.username`、`users.email` 唯一。
- `users(role, status)` 用于后台用户筛选。
- `user_sessions(user_id, expires_at)` 用于会话清理。
- 定时删除超过过期时间 30 天且已撤销的会话，禁止按用户批量物理删除仍在有效期内的会话。

## 5. 接口设计

接口均挂在 `/api/v1` 下。

### 5.1 注册

`POST /auth/register`

请求：

```json
{
  "studentNo": "2023001001",
  "username": "study_2023001001",
  "displayName": "张同学",
  "password": "Example123",
  "email": "student@example.edu.cn"
}
```

规则：

- `studentNo` 长度 4-32，只允许字母、数字和 `-`。
- `username` 长度 4-32，只允许字母、数字和下划线，不区分大小写唯一。
- `displayName` 长度 2-64，去除首尾空白。
- 密码长度 8-32，至少包含一个字母和一个数字。
- 邮箱可选，格式合法且不超过 128 字符。
- 注册接口强制写入 `role=student`、`status=active`，忽略客户端提交的角色字段。
- 学号、用户名或邮箱冲突时返回 `409 CONFLICT`，提示“账号信息已存在”，不返回数据库唯一键细节。
- 成功后返回 201 和脱敏用户信息，不自动签发登录态。

### 5.2 登录

`POST /auth/login`

请求：

```json
{
  "account": "2023001001",
  "password": "Example123"
}
```

处理顺序：

1. 规范化账号并查询用户。
2. 用户不存在时仍执行一次固定成本的 bcrypt 比较，降低账号枚举风险。
3. 校验密码、用户状态和角色是否允许当前入口登录。
4. 创建 `user_sessions` 记录。
5. 签发 JWT，并更新 `last_login_at`。

成功响应：

```json
{
  "code": "OK",
  "message": "登录成功",
  "data": {
    "token": "<jwt>",
    "expiresAt": "2026-11-05T17:30:00+08:00",
    "user": {
      "id": 1,
      "studentNo": "2023001001",
      "username": "study_2023001001",
      "displayName": "张同学",
      "role": "student",
      "status": "active",
      "restrictionUntil": null
    }
  }
}
```

账号不存在、密码错误和账号停用入口应返回统一“账号或密码错误”；已经成功验证密码但账号被停用时，可返回“账号已停用，请联系管理员”。登录接口按 IP 和账号组合限流，例如 5 分钟内最多 10 次失败请求。

### 5.3 退出

`POST /auth/logout`

- 认证中间件读取 JWT 中的 `sid`。
- 事务内将该会话 `revoked_at` 设为当前时间。
- 重复退出保持幂等，当前 Token 已撤销时仍返回成功。
- 前端无论服务端退出是否成功，都清理本地 Token 和用户缓存。

### 5.4 当前用户

`GET /me`

返回脱敏资料、角色、账号状态、当前有效违约数和限制截止时间。不得返回 `password_hash`、会话 ID 或 JWT。

### 5.5 修改资料

`PATCH /me`

允许修改 `displayName`、`email`、`phone`、`avatarUrl`。所有字段均为可选，但请求至少包含一个字段。邮箱修改后必须再次检查唯一性。

### 5.6 修改密码

`PATCH /me/password`

```json
{
  "oldPassword": "Example123",
  "newPassword": "Example456"
}
```

- 验证旧密码后才能写入新哈希。
- 新密码不能与旧密码相同。
- 成功后撤销该用户全部有效会话，包括当前会话；接口返回成功后前端立即清理本地 Token 并跳转登录页。
- 密码字段不写日志，不保存在 Pinia 持久化数据中。

### 5.7 管理员停用用户

`PATCH /admin/users/:userId/status`

```json
{
  "status": "disabled",
  "reason": "违反系统使用约定"
}
```

管理员不能停用自己的账号，不能把最后一个有效管理员停用。停用用户时撤销其全部有效会话，并记录审计日志。第一版不实现管理员重置他人密码。

## 6. 会话与权限实现

### 6.1 JWT 载荷

```json
{
  "sub": "1",
  "role": "student",
  "sid": "c6d98aa7-7c61-4f86-b7f6-45fb7d5f1998",
  "jti": "5b83d09d-e4b6-4e66-a7d2-b780f6eccb13",
  "iat": 1793800000,
  "exp": 1793807200
}
```

载荷只保存身份校验所需的最小信息。昵称、学号、违约数等可变化信息不在 JWT 中缓存，由 `GET /me` 获取。

### 6.2 认证中间件

建议导出 `authenticate` 和 `requireRole(...roles)` 两个中间件：

```text
authenticate
  -> 解析 Bearer Token
  -> 验证签名与 exp
  -> 查询有效 session
  -> 查询 active user
  -> 注入 AuthContext

requireRole('admin')
  -> 检查 AuthContext.user.role
```

控制器不直接读取 Authorization 请求头。资源归属检查由服务方法显式接收当前用户，不能只依赖路由角色。

### 6.3 前端会话状态

- `useAuthStore` 保存 `token`、`currentUser` 和初始化状态。
- Token 使用 `sessionStorage` 而不是长期 `localStorage`，标签页关闭后默认失效。
- `sessionStorage` 中的 Token 仍可被 XSS 读取，因此生产环境必须配置 CSP，禁止 `unsafe-inline` 脚本、未经审核的第三方脚本和未经净化的 `v-html`。
- 用户昵称、反馈和备注按纯文本渲染；外链和头像地址只允许 `http`、`https`，不接受 `javascript:` 或 `data:`。
- 刷新页面时如果有 Token，先请求 `/me`，成功后再渲染受保护页面。
- Axios 请求拦截器只对非公开接口添加 Bearer Token。
- 收到 401 时清除会话，并携带 `redirect` 参数跳转登录页。
- 收到 403 时保留登录态，显示无权限页面，不自动退出。

不得把 JWT 放入 URL 查询参数、页面标题、错误日志和埋点属性。

## 7. 页面设计

### 7.1 登录页 `/login`

- 账号、密码、登录按钮。
- 支持回车提交，提交中禁用重复点击。
- 显示字段级错误和服务端通用错误。
- 登录成功后按角色跳转：学生到 `/home`，管理员到 `/admin/dashboard`。
- 已登录用户访问登录页时直接跳转到角色首页。

### 7.2 注册页 `/register`

- 学号、用户名、显示名称、邮箱、密码和确认密码。
- 前端规则与后端保持一致，但不能替代后端校验。
- 注册成功后跳转登录页并预填账号，不自动登录。

### 7.3 个人中心 `/profile`

- 展示学号、账号、角色、昵称、联系方式和账号状态。
- 资料编辑与密码修改分区。
- 展示当前违约次数和限制截止时间；限制中显示明确提示和可访问的违约记录入口。

## 8. 路由守卫

| 路由类型 | 未登录 | 学生 | 管理员 |
| --- | --- | --- | --- |
| 公开 | 放行 | 放行 | 放行 |
| `requiresAuth` | 跳转登录 | 放行 | 放行 |
| `requiresAdmin` | 跳转登录 | 跳转 403 | 放行 |

路由守卫只改善体验，接口权限仍由后端校验。未知路由显示 404，不把不存在的管理员页面伪装为登录页。

## 9. 异常与边界

| 场景 | 处理 |
| --- | --- |
| 用户名大小写不同但实际相同 | 唯一约束拒绝，返回账号已存在 |
| 注册时提交 `role=admin` | 服务端忽略并强制学生角色 |
| 账号停用后继续持有 Token | 认证中间件返回 `UNAUTHORIZED` |
| 管理员停用自己 | 返回 `CONFLICT` |
| 最后一名管理员被停用 | 返回 `CONFLICT` |
| 同一账号并发登录 | 允许创建多个会话，受会话数量上限约束 |
| 修改密码期间旧 Token 正在请求 | 事务提交后新请求失效，已开始请求按正常流程完成 |

会话数量建议每用户最多保留 5 个有效会话，超过时撤销最早会话，避免无限增长。

## 10. 测试用例

1. 合法学生注册成功后可以使用新账号登录。
2. 重复学号、用户名或邮箱分别注册失败。
3. 密码长度不足或缺少字母/数字时返回字段校验错误。
4. 登录错误账号和错误密码返回统一文案。
5. 停用用户无法登录，已有 Token 也失效。
6. 学生无法访问管理员状态变更接口。
7. 用户只能读取和修改自己的资料。
8. 退出后原 Token 调用受保护接口返回 401。
9. 修改密码后旧密码失效，历史会话按规则撤销。
10. 刷新页面后可通过 `/me` 恢复用户信息。
11. 路由直接访问管理员页面时，学生被拦截。
12. 响应和日志中未出现密码、哈希、Token。
13. 修改密码后，新旧所有会话均失效并要求重新登录。
14. 生产构建响应包含明确的 CSP，用户输入不能通过 `v-html` 注入脚本。
