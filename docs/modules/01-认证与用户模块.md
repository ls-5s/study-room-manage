## 1. 模块目标与边界

认证与用户模块负责学生注册、账号登录、退出、会话校验、个人资料、密码修改和管理员用户管理。其他业务模块通过统一的认证上下文获得当前用户，不自行解析 JWT，也不仅依靠前端隐藏按钮判断权限。

本模块完成后，系统应能可靠回答：

- 当前请求来自哪个用户。
- 当前请求使用的是哪个有效会话。
- 当前用户是 `student` 还是 `admin`。
- 当前账号是否可用，以及是否处于预约限制期。
- 当前用户是否有权访问目标页面或业务资源。

### 1.1 第一版固定口径

1. **只使用用户名登录**。学号、邮箱和手机号都不是登录标识。
2. 学生注册时必须填写学号、用户名和显示名称；邮箱可选，手机号可在个人中心补充。
3. 管理员不能自助注册，只能由受控初始化脚本创建。
4. 不实现短信验证码、第三方登录、忘记密码和 Refresh Token。
5. Access Token 有效期固定为 2 小时，每个用户最多保留 5 个有效会话。
6. 数据库中的角色和账号状态是权限判断的最终依据，JWT 中的角色只用于日志和兼容，不直接授权。

### 1.2 注册身份说明

第一版采用开放注册，系统只校验学号格式和唯一性，**不验证学号是否真实属于当前注册者**。因此该注册流程适用于课程设计和演示，不应被描述为学校实名身份认证。

如用于真实用户，必须在注册前增加以下任一机制：

- 对接学校统一身份认证。
- 由管理员导入待认领学号，学生注册时只能认领预置记录。
- 使用学校邮箱或其他可信渠道完成一次性验证。

身份核验属于后续产品迭代，不应在没有可信身份源时通过前端校验或自填字段伪装实现。

## 2. 角色与权限

| 能力 | 未登录 | 学生 | 管理员 |
| --- | --- | --- | --- |
| 注册、登录 | 允许 | 不适用 | 不适用 |
| 退出当前会话 | Token 无效时拒绝 | 允许 | 允许 |
| 查看和修改本人资料 | 禁止 | 允许 | 允许 |
| 修改本人密码 | 禁止 | 允许 | 允许 |
| 查看本人违约摘要 | 禁止 | 允许 | 读取本人资料时允许 |
| 查询其他用户 | 禁止 | 禁止 | 允许 |
| 停用或恢复用户 | 禁止 | 禁止 | 允许，受保护规则约束 |
| 访问管理员业务页面 | 禁止 | 禁止 | 允许 |

权限按以下顺序执行：

1. 验证 Token 签名和有效期。
2. 验证会话未撤销、未过期，且会话与 Token 一致。
3. 查询用户并检查 `status=active`。
4. 检查接口要求的角色。
5. 对预约、反馈和违约等资源检查资源归属。

前端路由守卫只改善体验。所有权限必须由后端中间件和服务层再次检查。

## 4. 数据设计

### 4.1 `users`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键、自增 | 用户 ID |
| `student_no` | VARCHAR(32) | 非空、唯一 | 学号；管理员使用固定内部编号 |
| `username` | VARCHAR(32) | 非空、唯一 | 唯一登录账号 |
| `display_name` | VARCHAR(64) | 非空 | 展示名称 |
| `email` | VARCHAR(128) | 可空、唯一 | 联系方式，不作为登录标识 |
| `phone` | VARCHAR(20) | 可空 | E.164 格式，不作为登录标识 |
| `avatar_url` | VARCHAR(512) | 可空 | 仅允许 `http`、`https` 地址 |
| `password_hash` | VARCHAR(100) | 非空 | bcrypt 哈希 |
| `role` | ENUM | 非空 | `student`、`admin` |
| `status` | ENUM | 非空 | `active`、`disabled` |
| `violation_count` | INT UNSIGNED | 默认 0 | 当前有效违约数缓存 |
| `restriction_started_at` | DATETIME UTC | 可空 | 当前限制开始时间 |
| `restriction_until` | DATETIME UTC | 可空 | 当前限制截止时间 |
| `last_login_at` | DATETIME UTC | 可空 | 最近成功登录时间 |
| `created_at` | DATETIME UTC | 非空 | 创建时间 |
| `updated_at` | DATETIME UTC | 非空 | 更新时间 |

`email` 的唯一索引允许多个 `NULL`。空字符串必须统一转换为 `NULL`，避免第二个用户清空邮箱时发生唯一键冲突。

### 4.2 规范化规则

所有注册、登录和资料更新入口必须调用同一个规范化模块。

- `username`：去除首尾空白，转换为 ASCII 小写；只允许 `[a-z0-9_]`，长度 4-32。
- `student_no`：去除首尾空白，将 ASCII 字母转为大写；只允许 `[A-Z0-9-]`，长度 4-32。
- `email`：去除首尾空白并转换为小写；空值转为 `null`。
- `display_name`：去除首尾空白；长度 2-64。
- `phone`：去除空格和连字符；11 位中国大陆号码转换为 `+86` 前缀，最终存储 E.164 格式；空值转为 `null`。
- `avatar_url`：去除首尾空白；空值转为 `null`；只接受可解析的 `http` 或 `https` URL，不接受用户名和密码嵌入 URL。

应用层必须先规范化，再写入数据库。数据库排序规则不能替代服务层规范化。学号不是登录标识，因此用户名与另一用户的学号相同不会造成登录歧义。

### 4.3 用户状态与违约字段

- `role` 只能由管理员初始化脚本或受控数据维护命令写入，普通用户接口不得修改。
- `status` 只能通过管理员状态管理接口或受控初始化脚本修改。
- `violation_count`、`restriction_started_at` 和 `restriction_until` 由违约模块维护。
- 本模块只能读取上述违约字段，不得在资料更新、登录或停用用户时自行重算。
- 停用用户不会删除历史预约、违约和反馈。

### 4.4 `user_sessions`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | CHAR(36) | 主键 | 会话 ID，写入 JWT `sid` |
| `user_id` | BIGINT UNSIGNED | 外键、非空 | 所属用户 |
| `jti` | CHAR(36) | 非空、唯一 | Token 唯一标识 |
| `expires_at` | DATETIME UTC | 非空 | 会话绝对过期时间 |
| `revoked_at` | DATETIME UTC | 可空 | 退出或停用时间 |
| `created_at` | DATETIME UTC | 非空 | 登录时间 |

认证中间件按 `id=sid AND jti=claim.jti AND user_id=sub` 查询会话，避免 Token 和会话记录只凭一个随机字段关联。

### 4.5 索引与会话清理

- `users.student_no`、`users.username`、`users.email` 唯一。
- `users(role, status, id)` 用于管理员筛选和状态管理。
- `user_sessions(user_id, expires_at)` 用于会话上限统计。
- `user_sessions(expires_at, revoked_at)` 用于清理。

每天执行一次会话清理。会话表不作为安全审计表，清理条件为：

```text
expires_at < now - 30 days
```

无论会话是否已撤销，都删除满足条件的记录。删除仍在有效期内或过期未满 30 天的会话必须被禁止。

## 5. 接口设计

所有业务接口位于 `/api/v1`，成功和失败响应遵循公共约定。

### 5.1 注册

`POST /auth/register`，公开接口。

```json
{
  "studentNo": "2023001001",
  "username": "study_2023001001",
  "displayName": "张同学",
  "password": "Example123",
  "email": "student@example.edu.cn"
}
```

规则：

- `studentNo`、`username` 和 `displayName` 必填，并按规范化规则处理。
- 密码长度 8-32，只允许可见 ASCII 字符，且至少包含一个字母和一个数字。
- 密码的 UTF-8 字节数不得超过 72，避免 bcrypt 静默截断。
- 邮箱可选；格式错误返回 `422 VALIDATION_ERROR`。
- 服务端强制写入 `role=student`、`status=active`，忽略客户端提交的 `role` 和 `status`。
- 任意唯一字段冲突统一返回 `409 CONFLICT` 和“账号信息已存在”。
- 成功返回 201 和脱敏用户信息，不自动签发登录态。
- 注册接口按 IP 限流；同一 IP 每小时最多 10 次注册请求。

### 5.2 登录

`POST /auth/login`，公开接口。

```json
{
  "username": "study_2023001001",
  "password": "Example123"
}
```

只查询 `username`。不得把 `student_no`、`email` 或 `phone` 与用户名组成模糊查询。

处理流程：

1. 规范化用户名并检查登录限流。
2. 按用户名读取用户；用户不存在时执行一次固定成本的 bcrypt 比较。
3. 校验密码。
4. 开启事务，对目标用户 `SELECT ... FOR UPDATE`。
5. 在锁内重新读取用户状态和 `password_hash`，确认与校验阶段一致。
6. 统计未撤销且未过期的会话；达到 5 个时撤销最早的有效会话。
7. 创建新会话并更新 `last_login_at`，提交事务。
8. 返回 JWT 和脱敏用户摘要。

成功响应：

```json
{
  "code": "OK",
  "message": "登录成功",
  "data": {
    "token": "<jwt>",
    "expiresAt": "2026-11-05T17:30:00+08:00",
    "user": {
      "id": 1,
      "username": "study_2023001001",
      "studentNo": "2023001001",
      "displayName": "张同学",
      "role": "student",
      "status": "active",
      "restrictionUntil": null
    }
  }
}
```

`restrictionUntil` 只在 `restriction_until > now` 时返回未来时间；已过期的历史限制字段在响应中返回 `null`。

账号不存在和密码错误统一返回 401 和“账号或密码错误”。只有密码正确但账号停用时，才返回 403、`FORBIDDEN` 和“账号已停用，请联系管理员”。

### 5.3 登录限流

登录失败分别计入两个独立窗口：

| 维度 | 上限 | 窗口 |
| --- | --- | --- |
| 规范化用户名 | 10 次失败 | 5 分钟 |
| 客户端 IP | 30 次失败 | 5 分钟 |

任一窗口超限返回 `429 RATE_LIMITED`，并提供 `Retry-After`。成功登录可以清除该用户名的失败计数，但不能清除 IP 计数。

第一版单实例可以使用进程内存储。多实例部署时必须使用共享限流存储；不得以“每台机器各有 30 次”为由放宽全局限制。

### 5.4 退出

`POST /auth/logout`

退出不经过常规 `authenticate`，而经过独立的 `verifyTokenOnly`：

1. 解析 Bearer Token。
2. 验证签名、固定算法、`exp` 和必要载荷。
3. 不要求会话当前仍有效，也不要求用户当前为 `active`。
4. 按 `sid` 查找会话。
5. 会话存在且 `revoked_at IS NULL` 时写入当前时间。
6. 会话不存在或已经撤销时直接返回成功。

响应规则：

- 有效 Token：200，包括重复退出和账号已停用后的退出。
- 签名错误、格式错误或 Token 已过期：401。

前端无论退出请求结果如何，都清理本地 Token、用户缓存和初始化状态。

### 5.5 当前用户

`GET /me`，所有已登录用户可访问。

返回本人完整但非敏感的账号资料：

```json
{
  "id": 1,
  "studentNo": "2023001001",
  "username": "study_2023001001",
  "displayName": "张同学",
  "email": "student@example.edu.cn",
  "phone": "+8613800138000",
  "avatarUrl": null,
  "role": "student",
  "status": "active",
  "violationCount": 2,
  "restrictionUntil": null
}
```

不得返回 `password_hash`、会话 ID、JWT 或其他用户的资料。

### 5.6 修改个人资料

`PATCH /me`，所有已登录用户可访问。

允许修改：

- `displayName`
- `email`
- `phone`
- `avatarUrl`

规则：

- 所有字段可选，但请求至少包含一个字段。
- 不允许修改 `username`、`studentNo`、`role`、`status` 和违约字段。
- 传入 `null` 或空字符串可以清空可空字段，并统一保存为 `NULL`。
- 邮箱冲突返回 `409 CONFLICT`，不暴露具体唯一键。
- 更新成功后返回最新本人资料。

### 5.7 修改密码

`PATCH /me/password`

```json
{
  "oldPassword": "Example123",
  "newPassword": "Example456"
}
```

处理规则：

1. 开启事务并锁定当前用户行。
2. 在锁内读取最新哈希并校验旧密码。
3. 校验新密码格式，且通过 bcrypt 比较确认新旧密码不同。
4. 写入新哈希。
5. 撤销该用户全部未撤销会话，包括当前会话。
6. 提交事务并返回成功。

接口成功后前端立即清理本地会话并跳转登录页。密码字段不得进入日志、Pinia 持久化、错误追踪或埋点。

### 5.8 管理员用户列表

`GET /admin/users`，仅管理员。

支持参数：

| 参数 | 说明 |
| --- | --- |
| `studentNo` | 学号完整匹配或按索引前缀搜索 |
| `username` | 用户名完整匹配或按索引前缀搜索 |
| `role` | `student` 或 `admin` |
| `status` | `active` 或 `disabled` |
| `page` | 默认 1 |
| `pageSize` | 默认 20，最大 100 |

学号和用户名使用不同筛选参数，不使用含义不清的 `account` 参数。

列表可以返回：

- 用户 ID
- 学号
- 用户名
- 显示名称
- 角色
- 状态
- 违约次数
- 当前有效限制截止时间
- 是否处于有效限制期

列表中的邮箱和手机号必须脱敏，例如 `s***@example.edu.cn`、`138****8000`。不得返回密码哈希、会话 ID、JWT 或完整联系方式。

### 5.9 管理员用户详情

`GET /admin/users/:userId`，仅管理员。

返回脱敏资料、账号状态、违约次数和限制摘要。详情同样不返回完整手机号、密码哈希、会话 ID 或 Token。

不存在的用户返回 404。

### 5.10 停用或恢复用户

`PATCH /admin/users/:userId/status`，仅管理员。

```json
{
  "status": "disabled",
  "reason": "违反系统使用约定"
}
```

`status` 只能是 `active` 或 `disabled`，`reason` 必填，长度 2-255。

管理员状态变更必须在同一事务中完成：

1. 如果目标角色为 `admin`，按 `id` 顺序锁定全部管理员记录。
2. 否则锁定目标用户记录。
3. 锁定后重新读取目标用户及其角色、状态。
4. 禁止管理员停用自己。
5. 停用有效管理员前，计算停用后的有效管理员数量；结果小于 1 时返回 409。
6. 更新目标状态。
7. 停用用户时撤销其全部未撤销会话；恢复用户时不恢复旧会话。
8. 写入 `audit_logs`。

审计写入失败时整体回滚。恢复操作不改变用户历史业务记录，也不改变违约限制。

第一版不提供管理员重置他人密码。

### 5.11 审计前置条件

管理员状态接口依赖系统基础模块的 `audit_logs` 表。`audit_logs` 迁移必须在该接口上线前执行。

如果只实施用户、会话和登录接口，可以先完成 M01 的认证主体；管理员状态管理只有在审计基础设施可用后才能标记完成。不得先提交状态更新，再异步补写审计。

## 6. JWT、会话与认证中间件

### 6.1 JWT 载荷

```json
{
  "sub": "1",
  "role": "student",
  "sid": "c6d98aa7-7c61-4f86-b7f6-45fb7d5f1998",
  "jti": "5b83d09d-e4b6-4e66-a7d2-b780f6eccb13",
  "iat": 1793800000,
  "exp": 1793807200
}
```

规则：

- 算法固定为 HS256，验证时显式指定 `algorithms: ['HS256']`。
- `sub` 是用户 ID 字符串，`sid` 是会话 ID，`jti` 是 Token 唯一标识。
- `role` 只供日志和展示参考，授权必须使用认证中间件从数据库读取的角色。
- 密钥来自 `JWT_SECRET`，生产环境至少 32 个随机字节。
- 不签发 Refresh Token。

### 6.2 `verifyTokenOnly`

该中间件只完成：

- 解析 Bearer Token。
- 验证签名、算法和 `exp`。
- 校验必要字符串载荷及 `exp > iat`。
- 注入最小 Token 上下文。

它只用于退出接口。不得用于业务接口，因为它不检查会话撤销和用户状态。

### 6.3 `authenticate`

```text
authenticate
  -> 验证 JWT
  -> 查询 id=sid、jti、user_id=sub 且 revoked_at 为空的会话
  -> 检查 session.expires_at > now
  -> 查询 user
  -> 检查 user.status=active
  -> 注入 AuthContext
```

任何一步失败都返回 401 `UNAUTHORIZED`，不区分“会话不存在”“会话已撤销”和“用户已停用”的细节。

### 6.4 `requireRole`

```text
requireRole('admin')
  -> 读取 AuthContext.user.role
  -> 角色不符时返回 403 FORBIDDEN
```

`requireRole` 必须在 `authenticate` 之后执行。资源归属检查由服务方法显式接收当前用户完成，不能只依赖路由角色。

### 6.5 会话数量与过期

有效会话定义为：

```text
revoked_at IS NULL
AND expires_at > now
```

同一用户并发登录时，先锁定用户行，再统计和撤销，最后写入新会话。该事务必须保证最终有效会话不超过 5 个。

## 7. 前端会话与权限

### 7.1 认证状态

`useAuthStore` 保存：

- `token`
- `currentUser`
- `initialized`
- `initializingPromise`

Token 保存在 `sessionStorage`，不写入 `localStorage`。标签页关闭后默认失效。

刷新受保护页面时：

1. 读取本地 Token。
2. 通过单例 Promise 请求 `/me`，避免并发重复请求。
3. 成功后将用户写入 Store，再渲染受保护页面。
4. 401 时清理 Token 和用户缓存，跳转登录页。

### 7.2 Axios 拦截器

- 登录和注册请求不携带旧 Token。
- 其他 `/api/v1` 请求在存在 Token 时添加 `Authorization: Bearer <token>`。
- 收到已登录业务请求的 401 时，清空认证状态并跳转 `/login`。
- 登录接口自身的 401 只显示“账号或密码错误”，不触发全局跳转。
- 403 时保留登录态，跳转无权限页面，不自动退出。
- 429 时显示后端 `Retry-After` 对应等待时间，不自动循环重试。

现有请求封装需要保留后端返回的安全业务文案和字段错误。前端不得因为统一错误处理而把所有登录失败都替换成同一条网络错误。

### 7.3 路由守卫

`router/guards.ts` 提供：

```text
requiresAuth
requiresAdmin
```

行为：

| 条件 | 行为 |
| --- | --- |
| 未登录访问 `requiresAuth` | 跳转 `/login?redirect=<内部路径>` |
| 学生访问 `requiresAdmin` | 跳转 `/403` |
| 管理员访问 `requiresAdmin` | 放行 |
| 已登录访问 `/login` 或 `/register` | 跳转角色首页 |
| 未知路由 | 显示 404 |

`redirect` 只接受站内绝对路径，必须拒绝协议相对 URL、外部域名和 `javascript:` 地址，防止开放重定向。

`/profile` 只设置 `requiresAuth: true`，不得设置 `access: 'student'`，因为管理员同样可以查看和修改本人资料。

### 7.4 安全渲染

- 昵称、反馈、备注和错误消息按纯文本渲染。
- 不使用未经净化的 `v-html`。
- 头像 URL 只允许 `http`、`https`。
- 生产环境配置 CSP，禁止 `unsafe-inline` 脚本和未经审核的第三方脚本。
- JWT 不得进入 URL、页面标题、日志、埋点或错误详情。

## 8. 页面设计

### 8.1 登录页 `/login`

- 用户名、密码和登录按钮。
- 学号不能作为登录账号；页面文案明确写“用户名登录”。
- 支持回车提交，请求中禁用按钮。
- 显示字段级错误、账号停用提示和限流等待时间。
- 登录成功后，学生进入 `/home`，管理员进入 `/admin/dashboard`。
- 已登录用户访问登录页时直接进入角色首页。

### 8.2 注册页 `/register`

- 学号、用户名、显示名称、邮箱、密码和确认密码。
- 用户名提示“仅支持字母、数字和下划线，登录时使用该用户名”。
- 注册成功后跳转登录页并预填用户名，不自动登录。
- 首版不展示虚假的“已通过学校认证”状态。

### 8.3 个人中心 `/profile`

- 学生和管理员都可访问。
- 展示学号、用户名、角色、昵称、邮箱、手机号、头像和账号状态。
- 资料编辑、密码修改和当前违约摘要分区展示。
- 用户本人可查看完整联系方式；管理员用户管理页面中的同类字段保持脱敏。
- 违约限制结束时显示“限制已结束”，不继续把过期时间展示为当前限制。

### 8.4 管理员用户管理 `/admin/users`

- 按学号、用户名、角色和状态筛选。
- 列表展示脱敏联系方式、违约次数和限制摘要。
- 停用或恢复必须填写原因并二次确认。
- 管理员不能停用自己或最后一名有效管理员。
- 状态操作使用独立请求锁和提交中状态，防止重复点击。
- 学生端导航不显示该菜单，后端接口仍执行管理员权限检查。

## 9. 并发与事务规则

| 操作 | 必须锁定的数据 | 必须原子完成 |
| --- | --- | --- |
| 登录 | 目标用户行 | 重查状态和密码哈希、会话上限处理、创建会话、更新登录时间 |
| 修改密码 | 目标用户行 | 校验旧密码、更新哈希、撤销全部会话 |
| 停用或恢复用户 | 目标用户；管理员操作先锁定全部管理员 | 状态更新、必要会话撤销、审计写入 |
| 两条管理员停用操作并发 | 全部管理员按主键顺序 | 重新计数并保证至少一名有效管理员 |

状态更新和审计写入必须在同一数据库事务中。普通访问日志可在提交后写入，不能替代审计表。

## 10. 异常与错误响应

| 场景 | HTTP | `code` | 处理 |
| --- | --- | --- | --- |
| 字段格式错误 | 422 | `VALIDATION_ERROR` | 返回字段错误 |
| 学号、用户名或邮箱重复 | 409 | `CONFLICT` | “账号信息已存在” |
| 登录账号不存在或密码错误 | 401 | `UNAUTHORIZED` | “账号或密码错误” |
| 密码正确但账号停用 | 403 | `FORBIDDEN` | “账号已停用，请联系管理员” |
| 登录失败次数超限 | 429 | `RATE_LIMITED` | 提供 `Retry-After` |
| Token 无效或已过期 | 401 | `UNAUTHORIZED` | 前端清理会话 |
| 会话撤销或用户停用 | 401 | `UNAUTHORIZED` | 不泄露具体原因 |
| 学生访问管理员接口 | 403 | `FORBIDDEN` | 不执行服务层操作 |
| 修改他人资料 | 403 | `FORBIDDEN` | 普通用户没有该入口 |
| 邮箱冲突 | 409 | `CONFLICT` | 不返回唯一键名称 |
| 管理员停用自己 | 409 | `CONFLICT` | 返回业务冲突 |
| 停用最后一名有效管理员 | 409 | `CONFLICT` | 事务回滚 |
| 目标用户不存在 | 404 | `NOT_FOUND` | 不返回内部表信息 |

响应中不得出现 SQL、堆栈、数据库地址、JWT、密码哈希或完整个人敏感信息。

## 11. 测试用例

### 11.1 注册与登录

1. 合法学生注册后可使用用户名登录。
2. 学号、用户名或邮箱重复分别返回统一 409 文案。
3. 用户名大小写和首尾空白规范化后仍识别为同一账号。
4. 学号规范化后保持唯一；学号不作为登录账号。
5. 密码长度、组成或 UTF-8 字节数不合规时返回字段校验错误。
6. 账号不存在和密码错误返回相同的 401 文案。
7. 停用用户不能登录；密码正确时返回 403。
8. 登录失败达到用户名或 IP 限流上限时返回 429 和 `Retry-After`。
9. 两个用户中一人的用户名等于另一人的学号时，双方仍能通过各自用户名正确登录。

### 11.2 会话与退出

10. 登录后访问 `/me` 返回当前用户。
11. 退出后原 Token 访问业务接口返回 401。
12. 同一有效 Token 连续退出两次，第二次仍返回 200，且不影响其他会话。
13. 账号停用后使用该账号 Token 退出仍返回 200。
14. Token 过期、签名错误或会话不存在时访问业务接口返回 401。
15. 连续创建 6 个会话后只保留最新 5 个有效会话。
16. 过期会话不计入 5 个有效会话上限。
17. 会话清理只删除过期超过 30 天的记录。

### 11.3 资料与密码

18. 空字符串可以把邮箱、手机号和头像清空为 `NULL`。
19. 修改邮箱为其他用户已占用地址返回 409。
20. 修改密码成功后旧密码失效，全部旧会话失效。
21. 修改密码与并发登录竞争时，新的有效会话由密码修改规则统一撤销。
22. 用户不能修改角色、状态、学号或用户名。

### 11.4 管理员权限

23. 学生调用任何 `/admin/users` 接口都返回 403。
24. 管理员可以查询用户，但列表和详情不返回密码、Token、会话 ID 或完整联系方式。
25. 管理员不能停用自己的账号。
26. 管理员不能停用最后一名有效管理员。
27. 两个管理员并发停用对方时，事务串行执行，最终至少有一名有效管理员。
28. 停用用户的业务状态更新、会话撤销和审计写入原子提交。
29. 管理员可以访问 `/profile` 并修改本人资料。
30. 恢复用户不会恢复其旧会话。

### 11.5 前端与安全

31. 刷新页面通过 `/me` 恢复用户信息。
32. 学生直接访问管理员页面时显示 403。
33. 登录后的外部 `redirect` URL 被拒绝，只允许站内路径。
34. 响应和日志不包含密码、哈希、JWT 或 Authorization 头。
35. 用户输入通过纯文本渲染，生产构建包含明确 CSP。
