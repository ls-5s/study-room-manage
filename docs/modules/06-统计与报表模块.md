# 统计与报表模块开发文档

> 模块编号：M06  
> 文档版本：V1.1  
> 依赖：[预约与签到](./03-预约与签到模块.md)、[违约管理](./04-违约管理模块.md)、[自习室与座位](./02-自习室与座位模块.md)  
> 当前状态：设计完成，待实现

## 1. 模块目标

统计与报表模块为管理员提供预约、签到、失约和座位利用情况的可视化摘要，并支持按当前筛选条件导出 CSV。

本模块的重点不是“画图”，而是统一指标口径。仪表盘卡片、趋势图、明细查询和导出文件必须使用相同日期边界和状态定义，否则论文中的统计结果与系统页面会相互矛盾。

## 2. 数据来源与统计范围

### 2.1 数据来源

实时指标从业务表查询，历史和已结束日期使用每日房间统计快照。业务表包括：

- `reservations`：预约量、状态、日期、自习室、时段和起止时间。
- `check_ins`：实际签到时间。
- `violations`：有效违约和撤销情况。
- `study_rooms`、`room_time_slots`、`seats`：容量、开放时长和资源维度。

增加快照表的目的不是单纯提升性能，而是固定“当天可开放座位时长”这一历史分母。否则管理员以后停用座位或修改时段时，昨天的利用率也会变化。

### 2.2 `daily_room_metrics`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键 | 快照 ID |
| `stat_date` | DATE | 非空 | 东八区业务日期 |
| `room_id` | BIGINT UNSIGNED | 外键 | 自习室 |
| `available_seat_minutes` | BIGINT UNSIGNED | 非空 | 当日可用座位分钟数 |
| `reservation_count` | INT UNSIGNED | 非空 | 非取消预约场次 |
| `checked_in_count` | INT UNSIGNED | 非空 | 已签到和已完成场次 |
| `no_show_count` | INT UNSIGNED | 非空 | 失约场次 |
| `used_seat_minutes` | BIGINT UNSIGNED | 非空 | 签到预约使用分钟数 |
| `finalized_at` | DATETIME | 非空 | UTC 冻结时间 |
| `created_at` | DATETIME | 非空 | 创建时间 |
| `updated_at` | DATETIME | 非空 | 更新时间 |

`daily_room_metrics(stat_date, room_id)` 唯一。每天 `01:10` 冻结前一天数据，给 00:00 后的状态任务留出重试时间；当前日始终实时计算，尚未结算完成时 `hasData` 根据已结算预约判断。管理员修改今天或未来的资源只影响当前实时值，不重新计算已冻结日期。

如果后台操作导致已冻结日期的预约发生合法变化，应由对应业务服务触发受影响日期的显式重算并写审计；普通统计查询不得静默重算历史。

### 2.3 日期边界

- 用户筛选日期使用 `Asia/Shanghai` 的自然日。
- 查询区间采用左闭右开：`startOfDay(dateFrom)` 到 `startOfDay(dateTo + 1 day)`。
- 单个查询范围最大 366 天。
- 必须传入 `dateFrom` 和 `dateTo`；未传时默认前 6 天至今天，共 7 个自然日。
- 返回 `timezone: "Asia/Shanghai"`，避免前后端对日界线理解不同。

## 3. 指标定义

### 3.1 预约提交量

```text
count(reservations.created_at in range)
```

该指标表示区间内新增预约请求中成功写入的数量，包含之后取消或失约的记录，不按预约使用日期归属。用于观察提交行为和系统使用热度。

### 3.2 预约场次量

```text
count(reservations.reserve_date in range)
```

可按自习室、时段和状态分组。取消记录是否纳入由查询参数 `includeCancelled` 决定，仪表盘默认不纳入取消记录。

### 3.3 已结算预约

```text
status IN ('checked_in', 'completed', 'no_show')
```

签到率和失约率使用该集合作为分母。未来仍为 `pending` 的预约不参与比率计算，避免上课日期尚未到达时签到率被人为拉低。

### 3.4 签到率

```text
signInRate =
  count(checked_in or completed)
  / count(checked_in or completed or no_show)
```

如果分母为 0，接口返回 `0`，并附 `hasData=false`，前端显示“暂无数据”而不是误导性的 0%。

### 3.5 失约率

```text
noShowRate = count(no_show) / settledReservationCount
```

撤销违约不改变预约的 `no_show` 状态。若报表需要“最终确认失约”，应使用有效违约数据另行展示，不能悄悄改变历史预约状态。

### 3.6 座位利用率

使用已签到预约的使用时长近似：

```text
occupiedSeatMinutes = sum(end_at - start_at)

availableSeatMinutes =
  daily_room_metrics.available_seat_minutes

utilizationRate = occupiedSeatMinutes / availableSeatMinutes
```

第一版按预约时间长度计算利用，与具体签到时刻解耦。当前日的分母按当前静态容量和有效时段实时计算，并在当天计算时排除停用房间、维修座位和停用时段；历史日读取已冻结的 `available_seat_minutes`。日终任务把当时分母写入 `daily_room_metrics`，后续资源状态变化不会改写历史报表。

该指标是运营近似值，不是门禁传感器数据。论文中应明确说明计算方法。

### 3.7 今日卡片

| 卡片 | 口径 |
| --- | --- |
| 今日预约 | `reserve_date = today` 且状态不是 `cancelled` 的场次数 |
| 今日签到 | `reserve_date = today` 且状态为 `checked_in/completed` 的场次数 |
| 今日失约 | `reserve_date = today` 且状态为 `no_show` 的场次数 |
| 今日利用率 | 今日有效场次时长除以今日可用座位时长 |

卡片区域显示统一刷新时间和当前数据截止时间。

## 4. 接口设计

### 4.1 仪表盘概览

`GET /admin/statistics/overview?date=2026-11-05`

响应：

```json
{
  "date": "2026-11-05",
  "timezone": "Asia/Shanghai",
  "generatedAt": "2026-11-05T15:20:00+08:00",
  "cards": {
    "reservationCount": 128,
    "checkedInCount": 96,
    "noShowCount": 8,
    "utilizationRate": 0.62
  },
  "rates": {
    "signInRate": 0.9231,
    "noShowRate": 0.0769,
    "hasSettledData": true
  }
}
```

比率在接口中保留 4 位小数。前端显示百分数时统一乘以 100 并保留 1 位。

### 4.2 趋势与维度统计

`GET /admin/statistics/trend`

参数：

```text
dateFrom=2026-11-01
dateTo=2026-11-07
groupBy=day|room|slot
roomId=12              可选
```

响应：

```json
{
  "dateFrom": "2026-11-01",
  "dateTo": "2026-11-07",
  "groupBy": "day",
  "items": [
    {
      "key": "2026-11-01",
      "label": "11-01",
      "reservationCount": 92,
      "checkedInCount": 74,
      "noShowCount": 5,
      "signInRate": 0.9367,
      "utilizationRate": 0.54
    }
  ]
}
```

分组规则：

- `day`：按 `reserve_date` 分组，补齐没有数据的日期为 0。
- `room`：按自习室分组，返回名称、容量和四项指标。
- `slot`：按开放时段分组，返回时段标签、起止时间和指标。

只允许上述枚举，不接受客户端传入 SQL 表达式、任意字段名或排序表达式。

### 4.3 CSV 导出

`GET /admin/statistics/export`

参数复用 `dateFrom`、`dateTo`、`groupBy`、`roomId`。权限仅为管理员。

建议文件名：

```text
study-room-report-20261101-20261107.csv
```

响应头：

```text
Content-Type: text/csv; charset=utf-8
Content-Disposition: attachment; filename="study-room-report-20261101-20261107.csv"
```

CSV 固定列：

```text
分组,分组名称,预约数,已签到数,失约数,签到率,失约率,利用率
```

导出规则：

- 文件以 UTF-8 BOM 开头，保证 Excel 正确识别中文。
- 使用逗号分隔，字段统一双引号包裹并转义内部双引号。
- 时间、比率和空值格式固定，不在导出过程中改变业务口径。
- 单元格以 `= + - @` 开头时必须加前导单引号，防止 CSV 公式注入。
- 流式导出期间仍限制最大 366 天。

## 5. 查询实现

### 5.1 查询分层

```text
statistics.controller
  -> statistics.service
     -> statistics.repository
        -> reservations / check_ins / resources
```

服务层负责日期规范化、范围和比率计算；仓储层负责聚合查询。避免在 ECharts 页面中通过多次普通列表接口拉取全量预约再自行计算。

### 5.2 聚合建议

- 概览接口在同一个只读事务中读取所有卡片和比率数据，事务隔离级别使用 `REPEATABLE READ`，保证多个聚合查询基于同一数据快照。
- 趋势接口先取分组统计，再在服务层补齐缺失日期。
- 按房间和时段分组时使用主键或稳定外键，不使用名称做连接条件。
- 历史利用率分母读取 `daily_room_metrics`，当前日分母按开放时段与日期的笛卡尔组合实时计算。
- 比率分母为 0 时返回明确的空数据语义。
- 为统计日期范围增加慢查询日志；超过 500ms 时检查索引和查询计划。

### 5.3 缓存

第一版不强制引入 Redis。若单个概览查询明显超过性能目标，可增加 30-60 秒进程内缓存，但必须：

- 缓存键包含日期、房间和分组维度。
- 管理员手动刷新时可以绕过缓存。
- 多实例部署时接受短暂不一致，或改用共享缓存。
- 不缓存包含个人明细的导出文件。

## 6. 前端页面

### 6.1 仪表盘 `/admin/dashboard`

- 顶部日期选择和刷新按钮。
- 四个指标卡片，显示指标值、口径短说明和更新时间。
- 预约趋势折线图。
- 签到率和失约率组合图。
- 房间利用率排行和时段分布。
- 无数据时显示空状态，不渲染具有误导性的 0 折线。

### 6.2 统计报表 `/admin/reports`

- 日期范围、房间和分组维度筛选。
- 表格与图表数据使用同一次或同一组筛选参数。
- 支持导出当前结果，导出期间显示加载态并防止重复点击。
- 浏览器下载失败时显示可读错误，不把二进制错误响应当成 JSON。

ECharts 组件应使用 `dispose` 清理实例；窗口尺寸变化时调整图表大小。图表颜色不作为唯一的数值表达方式，表格和提示中必须提供文字数值。

## 7. 权限与安全

- 所有统计和导出接口仅管理员可访问。
- 统计响应只包含聚合值；学生姓名、学号等个人字段不出现在公开图表接口。
- 管理员专用明细需要进一步权限和审计时可后续增加，第一版不混入统计导出。
- 禁止接受任意 SQL、字段名或无限日期范围。
- 图表和导出不包含密码、Token、数据库信息。

## 8. 校验与验收

统计模块最容易出现“页面看起来正常但口径错误”的问题。验收时使用固定测试数据：

| 预约 | 状态 | 时长 | 结果 |
| --- | --- | --- | --- |
| A | `completed` | 2h | 计入已结算、签到、利用率 |
| B | `checked_in` | 2h | 计入已结算、签到、利用率 |
| C | `no_show` | 2h | 计入已结算和失约，不计利用率 |
| D | `pending` 未来 | 2h | 不计签到率分母 |
| E | `cancelled` | 2h | 默认不计场次和利用率 |

手工计算：

```text
settled = 3
signInRate = 2 / 3 = 0.6667
noShowRate = 1 / 3 = 0.3333
```

仪表盘、趋势查询和 CSV 导出必须得到相同结果。

## 9. 测试用例

1. 默认日期范围返回最近 7 天。
2. 超过 366 天的查询被拒绝。
3. 无结算数据时签到率返回明确的空状态。
4. 未来待签到预约不拉低签到率。
5. 取消预约默认不计入使用场次。
6. 按日、房间、时段三种分组返回稳定字段。
7. 无数据日期按约定补齐为 0。
8. 页面图表数值与概览接口一致。
9. 导出列顺序和中文表头正确。
10. CSV 用 Excel 打开无乱码。
11. 含公式前缀的文本不会执行公式。
12. 学生访问统计接口返回 403。
13. 单个统计接口在目标测试数据量下 P95 不超过 500ms。
14. 冻结昨天数据后停用若干座位，昨天的利用率保持不变。
15. 概览的多个聚合值来自同一只读事务快照。
