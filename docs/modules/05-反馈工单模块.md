## 1. 模块目标

反馈工单模块为学生提供占座举报和使用问题反馈渠道，为管理员提供核实、处理和结果记录入口。

第一版支持：

- 占座举报。
- 座位或自习室设施问题。
- 环境与卫生问题。
- 其他使用问题。

第一版不支持附件、匿名反馈、实时对话、工单分派、学生补充和重新打开工单。`processing` 仅表示管理员已开始处理，不表示工单被分配给某个人。

## 3. 数据设计

### 3.1 `feedback_tickets`

| 字段                 | 类型            | 约束       | 说明             |
| -------------------- | --------------- | ---------- | ---------------- |
| `id`                 | BIGINT UNSIGNED | 主键       | 工单 ID          |
| `user_id`            | BIGINT UNSIGNED | 外键、非空 | 提交学生         |
| `room_id`            | BIGINT UNSIGNED | 外键、可空 | 相关自习室       |
| `seat_id`            | BIGINT UNSIGNED | 外键、可空 | 相关座位         |
| `room_name_snapshot` | VARCHAR(64)     | 可空       | 提交时自习室名称 |
| `seat_no_snapshot`   | VARCHAR(32)     | 可空       | 提交时座位编号   |
| `type`               | ENUM            | 非空       | 工单类型         |
| `description`        | TEXT            | 非空       | 问题描述         |
| `status`             | ENUM            | 非空       | 四种工单状态     |
| `result`             | TEXT            | 可空       | 管理员处理结果   |
| `handled_by`         | BIGINT UNSIGNED | 外键、可空 | 最近处理管理员   |
| `processed_at`       | DATETIME        | 可空       | 首次开始处理时间 |
| `closed_at`          | DATETIME        | 可空       | 解决或驳回时间   |
| `created_at`         | DATETIME        | 非空       | 提交时间         |
| `updated_at`         | DATETIME        | 非空       | 更新时间         |

工单类型为 `occupied_seat`、`equipment`、`environment`、`other`。工单状态为 `pending`、`processing`、`resolved`、`rejected`。

### 3.2 约束与索引

- 所有业务外键使用 `ON UPDATE RESTRICT ON DELETE RESTRICT`，历史工单不随用户或资源删除。
- `seat_id` 非空时必须存在 `room_id`，数据库和业务校验均保证该约束。
- 索引覆盖用户与提交时间、状态与提交时间、房间与座位、类型与提交时间。
- 提交时保存房间和座位名称快照，历史工单不因资源改名而漂移。
- 原始描述、提交人和资源快照创建后不可修改。

## 4. 状态机

```text
pending
  ├─ 开始处理 -> processing
  └─ 直接驳回 -> rejected

processing
  ├─ 标记解决 -> resolved
  └─ 驳回 -> rejected

resolved / rejected
  └─ 终态，不允许再次修改
```

| 当前状态     | 目标状态     | 必填字段 | 时间字段                                    |
| ------------ | ------------ | -------- | ------------------------------------------- |
| `pending`    | `processing` | 无       | 设置 `processed_at`                         |
| `pending`    | `rejected`   | `result` | 只设置 `closed_at`，`processed_at` 保持为空 |
| `processing` | `resolved`   | `result` | 设置 `closed_at`                            |
| `processing` | `rejected`   | `result` | 设置 `closed_at`                            |

非法转换和终态重复处理返回 `409 CONFLICT`。每次合法转换都在同一事务中更新工单并写入 `audit_logs`；审计写入失败时整体回滚。

审计日志只保存工单 ID、类型、操作管理者和前后状态，不复制完整问题描述或处理结果。

## 5. 接口契约

所有接口使用现有统一响应格式，前缀为 `/api/v1`。

### 5.1 学生提交

`POST /feedback-tickets`

请求：

```json
{
  "type": "occupied_seat",
  "roomId": "12",
  "seatId": "205",
  "description": "该座位从上午开始一直放置物品，现场无人使用。"
}
```

响应状态为 201：

```json
{
  "id": "1001",
  "status": "pending",
  "createdAt": "2026-11-11T15:00:00+08:00"
}
```

校验规则：

- `description` 去除首尾空白后为 5–1000 字。
- 占座举报必须同时提供 `roomId` 和 `seatId`。
- 提供 `seatId` 时必须提供 `roomId`，且座位必须属于对应自习室。
- 房间或座位当前停用不阻止问题上报，但资源必须真实存在。
- 客户端不能指定提交人、状态、处理人或时间字段。
- 每个学生每分钟最多提交 3 条、每小时最多 10 条；超限返回 `429 RATE_LIMITED` 和 `Retry-After`。

### 5.2 学生查询

`GET /me/feedback-tickets`

支持 `status`、`type`、`page`、`pageSize`，按提交时间倒序。

`GET /me/feedback-tickets/:id`

返回本人问题描述、资源快照、状态、结果和关键时间。学生访问他人工单或不存在工单均返回固定 `404 NOT_FOUND`。学生响应不包含管理员内部 ID 和审计快照。

### 5.3 管理员查询

`GET /admin/feedback-tickets`

支持：

- `status`、`type`、`roomId`。
- `dateFrom`、`dateTo`，按提交时间筛选。
- `studentNo`，精确匹配学号。
- `keyword`，匹配房间快照、座位编号和问题描述。
- `page`、`pageSize`。

响应在分页数据外返回不受当前筛选影响的全局状态汇总：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 10,
  "total": 0,
  "summary": {
    "pending": 0,
    "processing": 0,
    "resolved": 0,
    "rejected": 0,
    "total": 0
  }
}
```

管理员默认排序为待处理、处理中优先，再按提交时间升序和工单 ID 升序。

`GET /admin/feedback-tickets/:id`

返回学生必要身份、资源、完整描述、处理结果、最后处理人和由审计日志生成的同事务时间线。

### 5.4 管理员处理

`PATCH /admin/feedback-tickets/:id`

```json
{
  "status": "resolved",
  "result": "已现场核实，物品已由管理员联系物主取走。"
}
```

`result` 去除首尾空白后为 2–1000 字。成功返回更新后的管理员详情和最新时间线。

## 6. 权限与隐私

- 提交、本人列表和本人详情只允许 `student` 角色。
- 管理员查询和处理只允许 `admin`、`super_admin`。
- 学生端路由同时由前端角色守卫和后端学生角色中间件保护。
- 管理员仅返回学号、用户名和显示名，不返回密码、邮箱、手机号或 Token。
- 页面中的描述和结果全部使用文本插值，不使用 `v-html`。
- 站点日志只记录工单 ID、类型和状态，不记录完整问题描述。
- 处理结果不得写入其他学生个人隐私。

## 7. 前端页面

### 7.1 学生 `/feedback`

- “提交反馈”和“我的反馈”双标签页。
- 反馈类型、自习室、座位和描述表单。
- 占座举报动态要求房间和座位；其他类型资源可选。
- 选择房间后通过现有自习室和座位接口载入座位摘要。
- 提交失败保留已填写内容；成功后展示工单编号和查看入口。
- 我的反馈支持状态、类型筛选、分页和详情抽屉。
- 待处理时不显示空白结果框，已解决与已驳回使用不同状态色。

### 7.2 管理员 `/admin/feedback`

- 顶部显示待处理、处理中、已解决和已驳回数量，点击汇总卡可快速筛选。
- 支持状态、类型、房间、提交日期、学号和关键词筛选。
- 工单队列显示学生、问题摘要、资源、提交时间和状态。
- 详情抽屉展示完整描述、处理结果和处理时间线。
- `pending` 可开始处理或驳回；`processing` 可解决或驳回。
- 解决和驳回使用独立结果对话框，必须填写结果，提交中禁用重复操作。

页面复用现有设计令牌和 Element Plus，支持桌面、移动端及明暗主题。

## 8. 演示数据

执行：

```powershell
pnpm --dir backend db:seed:feedback
```

种子脚本可重复执行，并完成以下工作：

- 创建或复用演示学生 `feedback_demo`。
- 创建或复用演示管理员 `feedback_admin`。
- 生成待处理、处理中、已解决和已驳回四类状态工单。
- 为已处理工单写入对应审计时间线。
- 首次创建账号时把随机密码写入本地 `backend/.env`；脚本和仓库不保存真实密码。
- 已存在演示工单时不重复创建。

## 9. 测试与验收

已实现单元测试：

- 有效占座举报规范化。
- 占座举报缺少房间或座位。
- 只提供座位、不提供自习室。
- 描述最短和最长边界。
- 合法状态转换。
- 解决和驳回结果必填。
- 跳过处理中和修改终态返回 409。

完成验收时执行：

```powershell
pnpm --dir backend test
pnpm --dir backend typecheck
pnpm --dir backend lint
pnpm --dir backend build
pnpm --dir frontend typecheck
pnpm --dir frontend lint
pnpm --dir frontend build
```

真实接口闭环已验证：

1. 学生登录并读取演示工单。
2. 学生创建新工单，初始状态为 `pending`。
3. 管理员读取全局汇总和筛选列表。
4. 跳过 `processing` 直接解决返回 409。
5. 管理员依次进入 `processing` 和 `resolved`。
6. 状态变化生成两条审计时间线。
7. 学生读取到最终状态和解决结果。
