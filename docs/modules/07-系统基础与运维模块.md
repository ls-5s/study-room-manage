# 系统基础与运维模块开发文档

> 模块编号：M07  
> 文档版本：V1.3  
> 依赖：无业务模块前置依赖  
> 被依赖：所有业务模块  
> 当前状态：基础工程已实现，业务基础设施待扩展

## 1. 模块目标

系统基础与运维模块提供配置、数据库连接、HTTP 应用、统一响应、错误处理、日志、定时任务、数据库迁移、健康检查和部署能力。业务模块依赖这些公共能力，不能各自实现不同格式的错误响应或数据库连接。

## 2. 已完成基线

当前工程已经具备：

- `backend/src/app.ts` 创建 Express 应用并配置中间件。
- `backend/src/server.ts` 启动 HTTP 服务。
- `backend/src/config/env.ts` 读取并校验环境变量。
- `backend/src/config/database.ts` 创建 Sequelize 连接。
- `backend/src/routes/system.routes.ts` 提供健康检查。
- `backend/src/types/api.ts` 定义 `ApiResponse` 和常见错误码。
- `backend/src/middleware/errors.ts` 处理 404、JSON 解析错误和内部错误。
- `backend/src/lib/logger.ts` 输出结构化日志。
- `backend/scripts/prepare-database.ts` 准备数据库和应用账号。
- `frontend/src/utils/request.ts` 统一请求、超时和响应封装。
- 健康检查接口仅用于部署与运维，不提供独立的用户端系统状态页面。

业务数据表尚未迁移创建，JWT、定时任务和管理员初始化仍属于后续实现。

## 4. 配置管理

### 4.1 现有环境变量

```text
HOST
PORT
NODE_ENV
CORS_ORIGINS
DB_HOST
DB_PORT
DB_NAME
DB_USER
DB_PASSWORD
DB_CONNECT_TIMEOUT_MS
DB_ACQUIRE_TIMEOUT_MS
DB_PROBE_TIMEOUT_MS
MYSQL_CONTAINER
```

### 4.2 计划新增环境变量

| 变量                      | 用途                       | 默认或要求             |
| ------------------------- | -------------------------- | ---------------------- |
| `JWT_SECRET`              | Access Token 签名          | 生产必须为高强度随机值 |
| `JWT_EXPIRES_IN`          | Token 有效期               | `2h`                   |
| `CHECK_IN_SIGNING_SECRET` | 签到码 HMAC                | 与 JWT 密钥分离        |
| `BCRYPT_COST`             | 密码哈希成本               | 12                     |
| `LOG_LEVEL`               | 日志级别                   | `info`                 |
| `BUSINESS_TIMEZONE`       | 业务日期解析和接口展示时区 | `Asia/Shanghai`        |
| `TRUST_PROXY`             | 反向代理信任设置           | 生产按部署拓扑配置     |

`.env.example` 只保留空值或安全示例，不提交真实密钥。前端 `VITE_` 变量会进入浏览器构建结果，禁止存放任何秘密。

配置读取应在启动时失败并给出缺失变量名称，而不是在业务请求中首次使用时失败。

数据库连接固定使用 UTC，不跟随宿主机时区：

```text
Sequelize: timezone: '+00:00'
MySQL session: time_zone = '+00:00'
服务内部时间比较: UTC
接口和业务日期边界: BUSINESS_TIMEZONE
```

不得只修改 `TZ` 环境变量并依赖 JavaScript 默认日期格式化完成上述转换。

## 5. HTTP 应用结构

中间件建议顺序：

```text
1. 请求 ID 和基本请求上下文
2. 访问日志
3. 安全响应头或反向代理安全头
4. CORS
5. JSON 请求体解析及大小限制
6. 登录、注册等接口限流
7. 业务路由
8. 404
9. 统一错误处理
```

CORS 只允许 `CORS_ORIGINS` 中的完整来源。生产环境禁止通配符。JSON 请求体上限固定为 256KB，超出返回 413 和 `BAD_REQUEST`；第一版没有文件上传，不额外放宽限制。

健康检查、就绪检查和业务路由都不应返回 HTML 错误页；所有客户端接口使用统一 JSON。

生产前端至少配置以下安全响应头，实际 API 域名按部署环境加入 `connect-src`：

```text
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' https: data:;
  connect-src 'self';
  object-src 'none';
  base-uri 'self';
  frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
```

## 6. 健康与就绪

### 6.1 `/api/v1/health`

- 不访问数据库。
- 返回 HTTP 200 和 `{ code: "OK", data: { status: "ok" } }`。
- 用于确认 Node.js 进程和 HTTP 路由正常。

### 6.2 `/api/v1/ready`

- 使用应用账号执行轻量数据库探测。
- 正常返回 200。
- 数据库不可达返回 503 和 `DATABASE_UNAVAILABLE`。
- 数据库异常不能导致 HTTP 进程退出；恢复后再次探测应重新成功。

### 6.3 系统设置

新增 `system_settings`：

| 字段          | 类型            | 说明             |
| ------------- | --------------- | ---------------- |
| `key`         | VARCHAR(100)    | 主键，稳定配置键 |
| `value_json`  | JSON/TEXT       | 规范化 JSON 值   |
| `description` | VARCHAR(255)    | 配置说明         |
| `updated_by`  | BIGINT UNSIGNED | 最近管理员       |
| `updated_at`  | DATETIME        | 更新时间         |

第一版配置至少包含预约提前天数、每日预约上限、签到宽限、违约阈值和限制天数。配置读取通过类型化服务，不在业务代码中散落字符串键。

## 7. 日志与可观测性

### 7.1 访问日志

每个请求记录：

```text
requestId
method
path
statusCode
durationMs
userId（如已认证）
```

不记录：

- 密码和密码哈希。
- Authorization 头和完整 JWT。
- 完整签到码和签名。
- 请求体中的敏感字段。
- SQL 绑定参数中的个人联系方式。

查询字符串只记录白名单字段，避免误写入敏感值。

### 7.2 业务事件

建议使用稳定事件名：

```text
auth.login.succeeded
auth.login.failed
auth.session.revoked
reservation.created
reservation.cancelled
reservation.checked_in
reservation.no_show
violation.created
violation.revoked
feedback.transitioned
report.exported
job.completed
job.failed
```

事件包含业务 ID、结果和耗时，不包含完整用户资料。

### 7.3 审计日志

`audit_logs` 记录管理员关键操作：

| 字段            | 类型            | 说明           |
| --------------- | --------------- | -------------- |
| `id`            | BIGINT UNSIGNED | 主键           |
| `operator_id`   | BIGINT UNSIGNED | 管理员         |
| `action`        | VARCHAR(64)     | 稳定动作名     |
| `resource_type` | VARCHAR(64)     | 资源类型       |
| `resource_id`   | BIGINT UNSIGNED | 资源 ID        |
| `before_json`   | JSON/TEXT       | 变更前必要字段 |
| `after_json`    | JSON/TEXT       | 变更后必要字段 |
| `reason`        | VARCHAR(255)    | 业务原因       |
| `request_id`    | VARCHAR(64)     | 关联请求       |
| `created_at`    | DATETIME        | 操作时间       |

审计信息不应包含密码、Token 或无关隐私。审核页面第一版可以作为系统基础接口提供，也可以直接在数据库留档；不得因为页面未完成而省略写入。

管理员取消预约、停用用户、撤销违约、处理反馈、修改规则和资源状态等关键动作，审计记录必须与业务更新在同一事务中提交。普通访问日志和性能事件在事务提交后写入；两类日志不能混为同一种可靠性要求。

## 8. 定时任务

### 8.1 任务清单

| 任务                   | 周期       | 幂等键                                                 |
| ---------------------- | ---------- | ------------------------------------------------------ |
| 超时未签到             | 每分钟     | 预约状态条件更新                                       |
| 已签到预约完成         | 每分钟     | 预约状态条件更新                                       |
| 创建每日分时段容量快照 | 每天 00:05 | `daily_slot_metrics(stat_date, room_id, slot_id)` 唯一 |
| 冻结每日分时段统计     | 每天 01:10 | `daily_slot_metrics(stat_date, room_id, slot_id)` 唯一 |
| 清理过期会话           | 每天       | `expires_at` 条件删除                                  |
| 清理过期签到码数据     | 无需持久化 | 内存或短缓存过期                                       |

容量快照任务使用唯一键保证幂等。应用启动时检查当天快照是否存在，缺失则在注册业务路由前补建；补建失败时只保留健康检查，按 5 分钟间隔重试。`00:05` 定时任务失败也按 5 分钟重试。若当天快照尚未成功创建，统计接口返回 `409 CONFLICT` 和“统计快照尚未生成”，不能按当前资源状态临时伪造历史分母。

`01:10` 冻结任务先验证目标日期不存在 `pending` 或已超过结束时间但仍为 `checked_in` 的预约；发现延迟状态时运行预约状态修复并延后冻结，不能把未结算数据直接当成最终结果。

### 8.2 任务运行器

- 应用启动后按配置启用，不阻塞 HTTP 监听。
- 前一次运行未结束时跳过本次运行。
- 单个任务异常记录日志，其他任务继续执行。
- 退出时停止调度并等待正在执行的任务完成。
- 测试环境可以禁用并手动调用任务函数。
- 所有任务函数支持注入 `now()`，便于时间边界测试。

多个应用实例同时运行时，依赖数据库条件更新保持业务幂等。若使用进程内锁，只能防止单实例重复执行，不能作为全局锁。

## 9. 数据库迁移与种子

### 9.1 迁移顺序

```text
001 create users and user_sessions
002 create audit_logs
003 add super_admin role
004 create study_rooms, room_time_slots, seats
005 fix seat batch index
后续 create reservations, check_ins and reservation_status_logs
后续 create violations, daily_slot_metrics and indexes
后续 create feedback_tickets
后续 create system_settings and related indexes
```

迁移登记表由 Sequelize Migration 管理。文件名和实际编号以代码为准，文档完成清单应回填真实编号。

### 9.2 种子数据

受控种子脚本至少创建：

- 一个管理员账号，凭据从环境变量读取。
- 两个示例自习室。
- 每室若干开放时段和座位。
- 可选的测试学生账号和示例预约。

演示资源的 `bookable_from` 设置为当天或过去日期；通过后台新增的正式资源默认从下一个业务日生效。

管理员初始化脚本必须幂等：账号已存在时不覆盖密码，除非使用显式 `--reset-password` 命令。默认输出不打印明文密码。

### 9.3 禁止事项

- 禁止启动时 `sequelize.sync()`。
- 禁止迁移中直接下发不可回滚的破坏性 DDL 而不备份。
- 禁止用种子脚本修改生产用户密码。
- 禁止把数据库密码、JWT 密钥和管理员密码写入源码或提交 `.env`。

## 10. 安全基线

- 密码使用 bcryptjs，成本不低于 12。
- JWT 密钥和签到码密钥分离，长度至少 32 随机字节。
- 登录失败、注册和预约接口限流。
- 服务端校验所有枚举、长度、日期和资源归属。
- SQL 查询参数化，排序字段使用白名单。
- API 错误不返回堆栈、SQL 或环境变量。
- 管理员关键操作写审计日志。
- 管理员关键操作与审计记录同事务提交。
- 签发二维码使用 HMAC，严格校验有效期和自习室。
- 日志脱敏，禁止记录完整认证信息和请求敏感字段。
- 生产前端配置 CSP，禁止 `unsafe-inline` 脚本和未经净化的 HTML 插值。
- 历史业务外键默认 `ON DELETE RESTRICT`，禁止级联删除预约、签到、违约、反馈和审计。

## 11. 测试基础

### 11.1 分层

| 层次     | 工具                    | 范围                                 |
| -------- | ----------------------- | ------------------------------------ |
| 单元测试 | Vitest                  | 配置解析、状态机、时间窗口、比率计算 |
| 服务测试 | Vitest + 测试数据库     | 事务、冲突、幂等                     |
| 接口测试 | Supertest + Vitest      | 状态码、响应格式、权限               |
| 前端测试 | Vitest + Vue Test Utils | 路由守卫、组件状态、交互             |
| 端到端   | Playwright              | 登录、预约、签到、反馈、导出         |

### 11.2 测试数据库

- 使用单独数据库或独立测试容器，禁止在开发库清理全部表。
- 每个测试用例使用事务回滚或专用清理脚本。
- 时间相关测试使用固定时钟，不依赖真实当前分钟。
- 并发测试至少同时发起两个真实数据库事务。

### 12.2 生产

```text
校验生产环境变量
  -> 备份数据库
  -> 构建前后端
  -> 执行迁移
  -> 启动后端
  -> 健康检查与就绪检查
  -> 部署静态前端
  -> 执行关键流程冒烟测试
```

生产要求：

- HTTPS 和反向代理。
- CORS 只允许正式前端域名。
- 数据库最小权限账号，不使用 MySQL root。
- 日志轮转和进程自动重启。
- 数据库定期备份并验证恢复。
- 应用优雅关闭，处理 SIGTERM/SIGINT。
- 在反向代理后正确配置客户端 IP 和代理信任。

## 13. 运维故障处理

| 现象                          | 检查                                     |
| ----------------------------- | ---------------------------------------- |
| `/health` 失败                | Node 进程、端口、反向代理                |
| `/health` 正常但 `/ready` 503 | 数据库账号、网络、连接池、数据库状态     |
| 登录全部 401                  | JWT 密钥是否跨实例一致、会话表是否可用   |
| 预约大量 409                  | 是否确实座位冲突，或活动唯一键误配置     |
| 定时任务未执行                | 调度是否启用、系统时间、任务日志         |
| 图表数值异常                  | 日期时区、取消与待签到口径、分母是否为 0 |
| CSV 中文乱码                  | UTF-8 BOM 和响应头                       |
| 前端 API 404                  | Vite 代理、`/api/v1` 前缀、后端路由汇总  |
