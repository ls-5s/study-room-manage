## 1. 模块目标

M07 为业务模块提供统一的配置读取、数据库连接、请求上下文、错误处理、日志、安全响应头、后台任务、数据库迁移、健康检查、系统设置和管理员运维页面。

第一版完成：

- 请求 ID 和访问日志。
- 四档结构化日志。
- API 安全响应头和 256KB 请求体限制。
- 健康检查、就绪检查和管理员系统状态。
- 预约、反馈、违约等全局业务参数。
- 预约状态与统计快照任务状态。
- 优雅关闭时排空后台任务。
- 迁移、受控种子和环境配置检查。

不包含 Redis、集中日志平台、分布式任务锁、自动备份托管和服务器反向代理配置。

## 3. 运行配置

后端启动时严格读取以下配置：

```text
HOST
PORT
NODE_ENV
CORS_ORIGINS
DB_HOST
DB_PORT
DB_NAME
DB_USER
DB_PASSWORD
DB_CONNECT_TIMEOUT_MS
DB_ACQUIRE_TIMEOUT_MS
DB_PROBE_TIMEOUT_MS
JWT_SECRET
JWT_EXPIRES_IN
CHECK_IN_SIGNING_SECRET
BCRYPT_COST
LOG_LEVEL
TRUST_PROXY
JOBS_ENABLED
```

- `LOG_LEVEL` 支持 `debug`、`info`、`warn`、`error`，默认 `info`。
- `TRUST_PROXY` 为可信反向代理跳数，范围 0–10，默认 0。
- `JOBS_ENABLED` 支持 `true/false/1/0`，默认 `true`。
- 业务时区固定为 `Asia/Shanghai`，不作为环境变量开放。
- 配置错误在启动阶段失败，并只返回变量名，不输出变量值。

配置检查命令：

```powershell
pnpm --dir backend system:check
```

命令只输出非敏感运行摘要，不显示 JWT、数据库密码或签到密钥。

## 4. HTTP 请求基础设施

中间件顺序：

```text
请求 ID 与 AsyncLocalStorage
  -> API 安全响应头
  -> 访问日志
  -> CORS
  -> 256KB JSON 解析
  -> 路由、认证与权限
  -> 404
  -> 统一错误处理
```

### 4.1 请求 ID

- 每个请求生成 UUID。
- 响应头返回 `X-Request-Id`。
- Express Request 和 AsyncLocalStorage 同时携带 request ID。
- 业务服务写审计日志时自动读取当前 request ID。
- 错误响应 `data.requestId` 与响应头一致。
- 后台任务没有 HTTP 上下文，审计 request ID 为 null。

### 4.2 访问日志

每个请求记录：

```text
requestId
method
path（不包含查询参数值）
statusCode
durationMs
userId
queryKeys
```

请求体、Authorization、密码、Token、验证码和查询参数值均不进入访问日志。

### 4.3 安全响应头

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- `Permissions-Policy` 禁用摄像头、麦克风与定位
- API CSP 使用 `default-src 'none'` 和 `frame-ancestors 'none'`
- 生产环境 HTTPS 请求增加 HSTS

JSON 请求体最大 256KB，超限返回 413 `BAD_REQUEST`。

## 5. 健康与系统状态

### 5.1 公共接口

`GET /api/v1/health`

- 不访问数据库。
- 返回 HTTP 200 和 `status=ok`。

`GET /api/v1/ready`

- 使用应用账号探测数据库。
- 正常返回 200。
- 数据库不可用返回 503 `DATABASE_UNAVAILABLE`。
- 数据库恢复后再次请求可重新成功。

`GET /api/v1/system/public-config`

公开返回：

```json
{
  "timezone": "Asia/Shanghai",
  "businessDate": "2026-11-11",
  "bookingWindowDays": 7
}
```

不包含任何密钥、管理配置或个人数据。

### 5.2 管理员状态

`GET /api/v1/admin/system/status`

返回：

- 当前 request ID。
- 服务名、版本、环境、启动时间和运行时长。
- 当前业务时间和固定时区。
- 数据库连接状态与探测延迟。
- 代理信任跳数和后台任务开关。
- 每个任务的状态、最近开始/结束时间、耗时、连续失败次数和安全错误名。

## 6. 系统设置

### 6.1 配置键

| 配置键                            | 范围   | 默认值 |
| --------------------------------- | ------ | ------ |
| `reservation.advanceDays`         | 1–30   | 7      |
| `reservation.dailyLimit`          | 1–10   | 2      |
| `reservation.createRatePerMinute` | 1–100  | 10     |
| `reservation.cancelRatePerMinute` | 1–100  | 10     |
| `feedback.createPerMinute`        | 1–60   | 3      |
| `feedback.createPerHour`          | 1–1000 | 10     |
| `violation.threshold`             | 1–20   | 3      |
| `violation.restrictionDays`       | 1–90   | 7      |

迁移 `012-seed-operational-settings` 写入预约和反馈默认值；违约默认值继续由迁移 `008` 提供。

### 6.2 接口与权限

`GET /api/v1/admin/system/settings`

- 普通管理员和超级管理员可读取。

`PUT /api/v1/admin/system/settings`

- 仅超级管理员可写。
- 必须提交全部三组配置。
- 任一字段非法时整体拒绝，不做部分更新。
- 配置写入与审计记录同事务提交。

### 6.3 生效方式

- 预约日期窗口、每日预约上限、预约创建/取消限流和反馈限流均读取系统设置。
- 当前单实例修改后立即清缓存并生效。
- 多实例部署时其他实例最多可能存在 30 秒缓存差异。
- 历史预约的签到窗口和资源快照不变。

## 7. 日志与审计

### 7.1 日志级别

`LOG_LEVEL` 控制最小输出级别：

```text
debug < info < warn < error
```

每条日志包含 UTC 时间、级别、稳定事件名和安全标量字段。

### 7.2 业务错误

5xx 日志包含：

- requestId
- method
- path
- statusCode
- 安全错误类名

不记录 SQL、请求体、堆栈原文、数据库凭据或 Token。

### 7.3 审计日志

- 管理员关键操作与业务更新同事务提交。
- 系统设置更新写入 `system.settings_updated`。
- 审计记录包含配置前后值、操作者、原因和当前 request ID。
- 审计不包含密码、Token 或不相关个人隐私。

## 8. 后台任务

现有任务：

| 任务                     | 名称                | 关键幂等保障                 |
| ------------------------ | ------------------- | ---------------------------- |
| 预约超时、完成和停机处理 | `reservation-state` | 状态条件更新、事务、签到与违约唯一约束 |
| 统计快照与历史冻结       | `statistics`        | 每日运行表和指标唯一键       |

任务状态：

- `idle`
- `running`
- `success`
- `error`

运行要求：

- 启动后立即执行一次，之后按周期运行。
- 前一次未完成时跳过本次。
- 支持注入 `now()` 和手动运行函数。
- 单个任务异常不阻止其他任务。
- 退出时清除定时器并等待正在执行的任务完成，再关闭数据库。
- `JOBS_ENABLED=false` 时仍可查看状态，但不启动调度。

路由：`/admin/system`

页面展示：

- API、数据库、运行时长和任务开关卡片。
- 服务版本、环境、业务时间、时区和代理跳数。
- 当前请求 ID 与复制操作。
- 后台任务状态表。
- 预约、反馈和违约参数表单。

权限：

- 普通管理员只读。

- 保存中禁用重复提交；字段错误定位到具体输入。

页面支持明暗主题、桌面和移动布局。

### 11.1 预约任务补充验收（2026-11-12）

原 `reservation-state` 调度器按 60 秒周期对真实 MySQL 中的隔离夹具执行，已验证：

- 已签到且到期的预约自动转 `completed`，写一条系统状态日志，重复运行不会重复写入。
- 待签到且超过签到截止、仍在 30 分钟停机豁免边界内的预约自动转 `no_show`，同事务生成唯一违约并更新用户计数与限制。
- 截止已超过 30 分钟的待签到预约自动取消，记录系统豁免原因，不产生违约。
- 历史失约累计通过任务既有的时间参数和限定单条预约的 Sequelize scope 验证；未把模拟时间传给扫描整个开发库的任务。

生命周期共 16 项检查通过，详见 [补充验收报告](../预约生命周期补充验收报告-2026-11-12.md)。本次未修改系统时钟或全局配置。临时脚本写入测试数据，不属于可任意重复执行的只读健康检查；全时长耐久运行、生产进程重启及多实例任务竞争仍需专项验证。

## 12. 部署与故障处理

生产部署流程：

```text
校验环境变量
  -> 备份数据库
  -> 构建前后端
  -> 执行迁移
  -> 启动后端
  -> 检查 health 和 ready
  -> 部署静态前端
  -> 执行关键流程冒烟测试
```

生产要求：

- HTTPS 和反向代理。
- 正确设置 `TRUST_PROXY`。
- CORS 仅允许正式前端来源。
- 数据库使用最小权限账号。
- 配置日志轮转、进程自动重启和数据库备份恢复演练。
- 静态前端 CSP 和值全由反向代理配置，不使用不一致的宽松规则。

故障定位：

| 现象                          | 排查                                     |
| ----------------------------- | ---------------------------------------- |
| `/health` 失败                | Node 进程、端口、反向代理                |
| `/health` 正常但 `/ready` 503 | 数据库账号、网络、连接池和数据库状态     |
| 请求错误                      | 使用 request ID 对照结构化日志           |
| 设置保存失败                  | 超级管理员权限、字段范围和数据库事务     |
| 任务未运行                    | `JOBS_ENABLED`、任务状态、最近错误和时间 |
| 设置未在另一实例生效          | 等待缓存过期并检查各实例日志             |
