# 自习室与座位模块开发文档

> 模块编号：M02  
> 文档版本：V1.3  
> 依赖：[公共约定](./README.md)、[认证与用户模块](./01-认证与用户模块.md)  
> 当前状态：设计完成，待实现

## 1. 模块目标

本模块维护可预约空间的基础数据，包括自习室、开放时段和座位布局，并向学生端提供服务查询、向预约模块提供可预约资源校验。

模块只管理“资源本身是否存在和启用”，某座位在某日期某时段是否已被占用由预约模块计算。座位静态状态与动态预约状态必须分开，避免把每小时的占用情况写成座位永久状态。

## 2. 功能范围

| 功能 | 学生 | 管理员 | 说明 |
| --- | --- | --- | --- |

| 查看自习室详情 | 允许 | 允许 | 包含开放时段和容量汇总 |
| 查看座位平面图 | 允许 | 允许 | 需要指定日期和时段 |
| 新增自习室 | 禁止 | 允许 | 默认关闭，配置完成后再开放 |
| 编辑自习室 | 禁止 | 允许 | 名称、位置、说明、状态 |
| 维护开放时段 | 禁止 | 允许 | 新增、修改、启停 |
| 批量新增座位 | 禁止 | 允许 | 按行列布局生成 |

第一版不实现跨校区、座位类型计费、设备借用和实时传感器占用检测。

## 4. 数据设计

### 4.1 `study_rooms`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键 | 自习室 ID |
| `name` | VARCHAR(64) | 非空 | 自习室名称 |
| `location` | VARCHAR(128) | 非空 | 楼栋和房间位置 |
| `description` | VARCHAR(500) | 可空 | 使用说明 |
| `grid_rows` | SMALLINT UNSIGNED | 非空 | 座位图最大行数 |
| `grid_columns` | SMALLINT UNSIGNED | 非空 | 座位图最大列数 |
| `status` | ENUM | 非空 | `open`、`closed`、`disabled` |
| `bookable_from` | DATE | 非空 | 最早可预约业务日期 |
| `created_at` | DATETIME | 非空 | 创建时间 |
| `updated_at` | DATETIME | 非空 | 更新时间 |

`open` 表示对学生开放预约，`closed` 表示临时关闭但可由管理员恢复，`disabled` 表示已停用并通常只在后台可见。自习室名称不要求全局唯一，但 `(location, name)` 组合必须唯一。

### 4.2 `room_time_slots`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键 | 时段 ID |
| `room_id` | BIGINT UNSIGNED | 外键、非空 | 所属自习室 |
| `label` | VARCHAR(32) | 非空 | 展示名称，如“上午一” |
| `start_time` | TIME | 非空 | 每日开始时间 |
| `end_time` | TIME | 非空 | 每日结束时间 |
| `status` | ENUM | 非空 | `active`、`inactive` |
| `bookable_from` | DATE | 非空 | 最早可预约业务日期 |
| `created_at` | DATETIME | 非空 | 创建时间 |
| `updated_at` | DATETIME | 非空 | 更新时间 |

时段是“每天的模板”，不存储具体日期。预约模块创建时把该时段组合为 `reserve_date + start_time` 和 `reserve_date + end_time`，写入预约起止时间快照。

### 4.3 `seats`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键 | 座位 ID |
| `room_id` | BIGINT UNSIGNED | 外键、非空 | 所属自习室 |
| `seat_no` | VARCHAR(32) | 非空 | 座位编号 |
| `row_no` | SMALLINT UNSIGNED | 非空 | 行号，从 1 开始 |
| `column_no` | SMALLINT UNSIGNED | 非空 | 列号，从 1 开始 |
| `status` | ENUM | 非空 | `available`、`maintenance`、`disabled` |
| `bookable_from` | DATE | 非空 | 最早可预约业务日期 |
| `remark` | VARCHAR(255) | 可空 | 维修或停用说明 |
| `created_at` | DATETIME | 非空 | 创建时间 |
| `updated_at` | DATETIME | 非空 | 更新时间 |

座位占用不是 `seats.status` 的枚举值。查询平面图时，响应动态返回 `reserved` 状态；维修和停用来自静态字段。这样同一座位不同日期、不同时段可以正确切换占用状态。

### 4.4 约束与索引

- `study_rooms(location, name)` 唯一，避免同一房间重复录入。
- `seats(room_id, seat_no)` 唯一。
- `seats(room_id, row_no, column_no)` 唯一，避免两个座位重叠在网格同一点。
- `room_time_slots(room_id, label)` 唯一。
- 为 `study_rooms(status, bookable_from)`、`room_time_slots(room_id, status, bookable_from)`、`seats(room_id, status, bookable_from)` 建立索引。
- 同一自习室的有效时段不得相互重叠。相邻时段可以共享边界，例如 `08:00-10:00` 和 `10:00-12:00`。
- 时段最短 30 分钟、最长 4 小时。

## 5. 接口设计

### 5.1 学生公开查询

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/study-rooms` | 公开 | 查询开放自习室列表 |
| GET | `/study-rooms/:roomId` | 公开 | 查询详情、有效时段和容量 |
| GET | `/study-rooms/:roomId/seats` | 公开 | 查询指定日期、时段座位状态 |

列表筛选参数：

```text
keyword      名称或位置关键词
date         可选，预约日期
startTime    可选，统一筛选开始时间
endTime      可选，统一筛选结束时间
page         页码
pageSize     每页数量
```

公开列表只返回 `status=open` 的自习室，不接受客户端通过状态参数读取已关闭或停用资源；管理员使用独立后台列表查看全部状态。

未同时提供 `date`、`startTime` 和 `endTime` 时，列表返回静态可预约座位数 `bookableSeatCount`，其值为当天已生效且状态为 `available` 的座位数，不代表某个时段仍有空位。

同时提供三个时间参数时，服务端为每个自习室查找 `start_time = startTime`、`end_time = endTime` 且 `bookable_from <= date` 的有效时段。存在匹配时段的自习室额外返回该房间自己的 `matchedSlot` 和 `availableSeatCount`；没有匹配时段的自习室不进入时间筛选结果。不得把某个房间的 `slotId` 直接用于其他房间的列表查询，因为时段 ID 属于单个自习室。

详情响应示例：

```json
{
  "id": 12,
  "name": "图书馆三层自习室",
  "location": "图书馆 3F-301",
  "description": "保持安静，禁止携带食物入内",
  "status": "open",
  "grid": {
    "rows": 8,
    "columns": 10
  },
  "seatCount": 76,
  "bookableSeatCount": 74,
  "timeSlots": [
    {
      "id": 31,
      "label": "上午一",
      "startTime": "08:00",
      "endTime": "10:00"
    }
  ]
}
```

### 5.2 座位可用性查询

`GET /study-rooms/:roomId/seats?date=2026-11-10&slotId=31`

响应：

```json
{
  "roomId": 12,
  "date": "2026-11-10",
  "slot": {
    "id": 31,
    "startAt": "2026-11-10T08:00:00+08:00",
    "endAt": "2026-11-10T10:00:00+08:00"
  },
  "seats": [
    {
      "id": 205,
      "seatNo": "A-01",
      "row": 1,
      "column": 1,
      "status": "available",
      "disabledReason": null
    },
    {
      "id": 206,
      "seatNo": "A-02",
      "row": 1,
      "column": 2,
      "status": "reserved",
      "disabledReason": null
    },
    {
      "id": 207,
      "seatNo": "A-03",
      "row": 1,
      "column": 3,
      "status": "maintenance",
      "disabledReason": "椅面维修"
    }
  ]
}
```

可用性优先级：

```text
自习室关闭/停用
  -> 全部 unavailable
座位 disabled
  -> disabled
座位 maintenance
  -> maintenance
存在 pending 或 checked_in 的有效预约
  -> reserved
其他
  -> available
```

查询只使用可用性服务，不允许前端自行根据静态座位状态推断是否可预约。创建预约时服务端必须重新计算，不能信任页面上的座位状态。

公开详情和座位查询同样检查自习室、时段和座位的 `bookable_from <= date`；未到生效日期的资源只能由管理员后台查看。

### 5.3 管理员接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/admin/study-rooms` | 查询全部状态的自习室 |
| GET | `/admin/study-rooms/:roomId` | 查询后台详情、全部时段和座位摘要 |
| POST | `/admin/study-rooms` | 新增自习室 |
| PATCH | `/admin/study-rooms/:roomId` | 修改信息或状态 |
| POST | `/admin/study-rooms/:roomId/time-slots` | 新增开放时段 |
| PATCH | `/admin/time-slots/:slotId` | 修改或启停时段 |
| POST | `/admin/study-rooms/:roomId/seats` | 批量新增座位 |
| PATCH | `/admin/seats/:seatId` | 修改座位 |

新增自习室默认 `status=closed`，配置至少一个有效时段和座位后才允许切换为 `open`。切换为 `open` 前检查：

- 至少有一个 `active` 时段。
- 至少有一个 `available` 座位。
- 网格尺寸能容纳全部座位坐标。
- 没有坐标冲突或重复编号。

批量新增座位请求：

```json
{
  "prefix": "A",
  "rows": 4,
  "columns": 6,
  "startRow": 1,
  "startColumn": 1,
  "skip": [
    { "row": 2, "column": 3 }
  ]
}
```

座位编号固定为 `prefix + "-" + 两位序号`。有效单元按行号升序、同一行按列号升序排列，序号从 `01` 开始连续生成，例如 `A-01`、`A-02`。不同批次的 `prefix` 必须在现有座位中唯一；编号或坐标冲突、部分失败时整个事务回滚。

## 6. 业务规则

### 6.1 开放时段

- 新增或修改时段时检查 `start_time < end_time`。
- 不接受跨午夜时段；如需跨日，拆成两个配置。
- 同一自习室有效时段不能重叠。
- 已有预约引用的时段不允许物理删除；可改为 `inactive`。
- 修改 `start_time` 或 `end_time` 前必须查询该时段是否仍被 `pending` 或 `checked_in` 预约引用。只要存在一条未结束预约，修改时间返回 `409 CONFLICT`。
- 修改时段文字名称不影响已有预约，可以直接执行。
- 需要调整时段结构时，应新建时段、停用旧时段，并让新预约使用新时段。
- 预约模块使用预约表中的时间快照，因此历史记录不会因时段停用而改变。
- 所有结构变更都写入 `bookable_from`。新建资源或恢复停用资源的 `bookable_from` 默认为下一个业务日；历史种子数据可以填写过去日期。
- 后台请求不能任意提交 `bookableFrom`。新增和恢复操作由服务端计算生效日；只有受控种子或数据修复脚本可以写入历史日期。

### 6.2 座位状态

- `available`：可创建新预约。
- `maintenance`：暂不可预约，需填写维修说明。
- `disabled`：长期停用，仍需保留历史预约关联。
- 将房间关闭、时段停用或座位改为维修/停用时，如果仍存在该资源的 `pending` 预约，状态更新返回 `409 CONFLICT` 并返回冲突预约数量。管理员必须先取消这些预约并记录原因。
- 如果仅存在当前 `checked_in` 预约，可以执行停止新预约的状态更新；当天容量快照已经生成，已签到学生继续使用，其他学生不能再预约。
- 系统不静默取消预约，也不会因为资源状态变化自动生成学生违约。
- 座位编号和行列坐标的修改要避免影响已完成的记录展示；若业务必须修改，应保留可追溯审计。

### 6.3 网格布局

- 行列号从 1 开始，必须位于 `1..grid_rows` 和 `1..grid_columns`。
- 减少网格尺寸前检查是否有座位超出范围。
- 未被占用的网格单元用于渲染过道，不代表座位。
- 第一版不提供拖拽布局；批量生成后再用编辑表单微调坐标。

### 6.4 资源变更生效边界

统计容量采用“当日计划容量快照”。为了避免管理操作在一天中间改变历史统计分母，资源维护遵循以下边界：

- 每天 `00:05` 为当日有效自习室和有效时段创建容量快照，记录可预约座位数和计划开放分钟数。
- 新增或重新启用自习室、启用新时段、批量新增座位或恢复可预约座位时，把 `bookable_from` 设置为下一个业务日，不依赖后台任务按时切换状态。
- 公开列表、座位可用性、创建预约和容量快照都必须满足 `bookable_from <= 目标业务日期`。
- 将房间关闭、将时段停用或将座位改为维修/停用可以立即阻止新预约，但不会修改当天已经生成的计划容量。
- 当天已有预约不会因房间、时段或座位状态变化自动取消，管理员必须通过预约管理处理并记录原因。
- 历史利用率 = 实际签到使用分钟数 / 当天计划开放座位分钟数。计划容量不会因当天维修而追溯减少，因此维护造成的空闲会体现在较低的利用率中。

## 7. 前端交互

### 7.1 首页 `/home`

- 自习室卡片展示名称、位置、开放状态和静态可预约座位数。
- 用户同时选择日期、开始时间和结束时间后，使用统一时间范围刷新列表；每个自习室返回自己匹配的时段和动态可用座位数。
- 支持关键字搜索，条件变化时取消上一次未完成的请求。
- 空结果显示“暂无符合条件的自习室”，请求失败显示重试按钮。

### 7.2 自习室详情 `/study-rooms/:id`

- 顶部显示基础信息。
- 日期选择范围为今天到系统允许的最晚日期。
- 时段以按钮组展示，过去时段的按钮禁用。
- 座位图与图例同时显示：空闲、已预约、维修、停用。
- 座位不可用时不能点击提交；右侧或底部展示选中的座位摘要。
- 点击“立即预约”进入预约确认流程，最终结果以创建预约接口为准。

### 7.3 后台自习室管理

- 列表支持状态筛选和关键词查询。
- 编辑页分为基本信息、开放时段和座位管理三个区域。
- 危险状态切换需要二次确认，展示对现有预约的可能影响。
- 批量新增座位需要先预览生成数量和编号示例，再提交。

## 8. 异常与并发

| 场景 | 处理 |
| --- | --- |
| 查询不存在的自习室 | `404 NOT_FOUND` |
| 时段不属于该自习室 | `VALIDATION_ERROR` |
| 日期格式错误或超出可预约范围 | `VALIDATION_ERROR` |
| 时段已停用 | 返回不可用，不显示为可预约选项 |
| 座位在查询后刚被预约 | 创建接口返回 `409 CONFLICT`，前端刷新座位图 |
| 批量座位与已有编号冲突 | 整体回滚并返回冲突编号摘要 |
| 把已关闭自习室改为开放但无座位 | `CONFLICT` |
| 关闭仍有待签到预约的资源 | `409 CONFLICT`，先取消预约或等待其结束 |

座位可用性查询不开启长事务。真正的并发约束由预约模块的座位锁定和唯一索引负责。

管理员修改自习室状态、时段或座位状态时必须开启写事务，并按“自习室 -> 时段 -> 座位”顺序操作。预约事务会持有自习室和时段的共享锁、座位的排他锁，资源修改必须等到相应预约事务提交后再继续，避免预约在“资源校验通过、记录尚未插入”的窗口内被关闭或改为维修。

## 9. 测试用例

1. 公开列表只返回允许展示的自习室。
2. 管理员可创建自习室、时段和座位。
3. 同一自习室重复座位编号被拒绝。
4. 行列坐标重复被拒绝。
5. 时段开始时间晚于结束时间被拒绝。
6. 同房间两个重叠时段被拒绝，边界相邻时段被允许。
7. 不同日期、时段下同一座位的动态状态不同。
8. 维修和停用座位始终不可预约。
9. 自习室关闭后全部座位标记为不可用。
10. 批量新增座位部分失败时无部分数据写入。
11. 学生调用管理员维护接口返回 403。
12. 座位图在无数据、接口失败和日期切换时状态正确。
13. 未选择日期和时段时不把静态可预约数误展示为动态可用数。
14. 关闭自习室与创建预约并发时，提交后预约状态和资源状态保持一致。
15. 跨自习室按 `08:00-10:00` 筛选时，各房间使用自己的匹配时段，而不是共用某一个 `slotId`。
16. 有时段存在待签到预约时修改其起止时间返回 409，预约时间不被改变。
17. 当天维修座位的实际使用下降不会改变当天计划容量快照。
18. 关闭仍有待签到预约的自习室被拒绝，取消预约后才能关闭。
19. 仅有已签到预约时允许关闭资源，现有学生不被自动取消或记为违约。
20. 当天把座位重新设为可用时，`bookable_from` 为次日，今天仍不能预约。
21. 容量快照、列表和创建预约对 `bookable_from` 的判断结果一致。
