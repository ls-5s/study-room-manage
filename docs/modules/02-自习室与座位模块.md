# 自习室与座位模块开发文档

> 模块编号：M02  
> 文档版本：V1.1  
> 依赖：[公共约定](./README.md)、[认证与用户模块](./01-认证与用户模块.md)  
> 当前状态：设计完成，待实现

## 1. 模块目标

本模块维护可预约空间的基础数据，包括自习室、开放时段和座位布局，并向学生端提供服务查询、向预约模块提供可预约资源校验。

模块只管理“资源本身是否存在和启用”，某座位在某日期某时段是否已被占用由预约模块计算。座位静态状态与动态预约状态必须分开，避免把每小时的占用情况写成座位永久状态。

## 2. 功能范围

| 功能 | 学生 | 管理员 | 说明 |
| --- | --- | --- | --- |
| 查询自习室列表 | 允许 | 允许 | 支持名称、位置和状态筛选 |
| 查看自习室详情 | 允许 | 允许 | 包含开放时段和容量汇总 |
| 查看座位平面图 | 允许 | 允许 | 需要指定日期和时段 |
| 新增自习室 | 禁止 | 允许 | 默认关闭，配置完成后再开放 |
| 编辑自习室 | 禁止 | 允许 | 名称、位置、说明、状态 |
| 维护开放时段 | 禁止 | 允许 | 新增、修改、启停 |
| 批量新增座位 | 禁止 | 允许 | 按行列布局生成 |
| 修改座位 | 禁止 | 允许 | 编号、位置、静态状态、备注 |
| 删除实体 | 禁止 | 禁止 | 使用停用状态保留历史 |

第一版不实现跨校区、座位类型计费、设备借用和实时传感器占用检测。

## 4. 数据设计

### 4.1 `study_rooms`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键 | 自习室 ID |
| `name` | VARCHAR(64) | 非空 | 自习室名称 |
| `location` | VARCHAR(128) | 非空 | 楼栋和房间位置 |
| `description` | VARCHAR(500) | 可空 | 使用说明 |
| `grid_rows` | SMALLINT UNSIGNED | 非空 | 座位图最大行数 |
| `grid_columns` | SMALLINT UNSIGNED | 非空 | 座位图最大列数 |
| `status` | ENUM | 非空 | `open`、`closed`、`disabled` |
| `created_at` | DATETIME | 非空 | 创建时间 |
| `updated_at` | DATETIME | 非空 | 更新时间 |

`open` 表示对学生开放预约，`closed` 表示临时关闭但可由管理员恢复，`disabled` 表示已停用并通常只在后台可见。自习室名称不要求全局唯一，但同一位置的名称建议唯一。

### 4.2 `room_time_slots`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键 | 时段 ID |
| `room_id` | BIGINT UNSIGNED | 外键、非空 | 所属自习室 |
| `label` | VARCHAR(32) | 非空 | 展示名称，如“上午一” |
| `start_time` | TIME | 非空 | 每日开始时间 |
| `end_time` | TIME | 非空 | 每日结束时间 |
| `status` | ENUM | 非空 | `active`、`inactive` |
| `created_at` | DATETIME | 非空 | 创建时间 |
| `updated_at` | DATETIME | 非空 | 更新时间 |

时段是“每天的模板”，不存储具体日期。预约模块创建时把该时段组合为 `reserve_date + start_time` 和 `reserve_date + end_time`，写入预约起止时间快照。

### 4.3 `seats`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT UNSIGNED | 主键 | 座位 ID |
| `room_id` | BIGINT UNSIGNED | 外键、非空 | 所属自习室 |
| `seat_no` | VARCHAR(32) | 非空 | 座位编号 |
| `row_no` | SMALLINT UNSIGNED | 非空 | 行号，从 1 开始 |
| `column_no` | SMALLINT UNSIGNED | 非空 | 列号，从 1 开始 |
| `status` | ENUM | 非空 | `available`、`maintenance`、`disabled` |
| `remark` | VARCHAR(255) | 可空 | 维修或停用说明 |
| `created_at` | DATETIME | 非空 | 创建时间 |
| `updated_at` | DATETIME | 非空 | 更新时间 |

座位占用不是 `seats.status` 的枚举值。查询平面图时，响应动态返回 `reserved` 状态；维修和停用来自静态字段。这样同一座位不同日期、不同时段可以正确切换占用状态。

### 4.4 约束与索引

- `study_rooms(location, name)` 建议唯一，避免同一房间重复录入。
- `seats(room_id, seat_no)` 唯一。
- `seats(room_id, row_no, column_no)` 唯一，避免两个座位重叠在网格同一点。
- `room_time_slots(room_id, label)` 唯一。
- 为 `study_rooms(status)`、`room_time_slots(room_id, status)`、`seats(room_id, status)` 建立索引。
- 同一自习室的有效时段不得相互重叠。相邻时段可以共享边界，例如 `08:00-10:00` 和 `10:00-12:00`。
- 时段最短 30 分钟、最长 4 小时。

## 5. 接口设计

### 5.1 学生公开查询

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| GET | `/study-rooms` | 公开 | 查询开放自习室列表 |
| GET | `/study-rooms/:roomId` | 公开 | 查询详情、有效时段和容量 |
| GET | `/study-rooms/:roomId/seats` | 公开 | 查询指定日期、时段座位状态 |

列表筛选参数：

```text
keyword      名称或位置关键词
status       open/closed；公开接口默认只返回 open
date         可选，预约日期
slotId       可选，开放时段
page         页码
pageSize     每页数量
```

未同时提供 `date` 和 `slotId` 时，列表返回静态可预约座位数 `bookableSeatCount`，其值为状态为 `available` 的座位数，不代表某个时段仍有空位。同时提供两者时，列表额外返回 `availableSeatCount`，该字段才表示对应日期和时段的动态可用数。

详情响应示例：

```json
{
  "id": 12,
  "name": "图书馆三层自习室",
  "location": "图书馆 3F-301",
  "description": "保持安静，禁止携带食物入内",
  "status": "open",
  "grid": {
    "rows": 8,
    "columns": 10
  },
  "seatCount": 76,
  "bookableSeatCount": 74,
  "timeSlots": [
    {
      "id": 31,
      "label": "上午一",
      "startTime": "08:00",
      "endTime": "10:00"
    }
  ]
}
```

### 5.2 座位可用性查询

`GET /study-rooms/:roomId/seats?date=2026-11-10&slotId=31`

响应：

```json
{
  "roomId": 12,
  "date": "2026-11-10",
  "slot": {
    "id": 31,
    "startAt": "2026-11-10T08:00:00+08:00",
    "endAt": "2026-11-10T10:00:00+08:00"
  },
  "seats": [
    {
      "id": 205,
      "seatNo": "A-01",
      "row": 1,
      "column": 1,
      "status": "available",
      "disabledReason": null
    },
    {
      "id": 206,
      "seatNo": "A-02",
      "row": 1,
      "column": 2,
      "status": "reserved",
      "disabledReason": null
    },
    {
      "id": 207,
      "seatNo": "A-03",
      "row": 1,
      "column": 3,
      "status": "maintenance",
      "disabledReason": "椅面维修"
    }
  ]
}
```

可用性优先级：

```text
自习室关闭/停用
  -> 全部 unavailable
座位 disabled
  -> disabled
座位 maintenance
  -> maintenance
存在 pending 或 checked_in 的有效预约
  -> reserved
其他
  -> available
```

查询只使用可用性服务，不允许前端自行根据静态座位状态推断是否可预约。创建预约时服务端必须重新计算，不能信任页面上的座位状态。

### 5.3 管理员接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/admin/study-rooms` | 新增自习室 |
| PATCH | `/admin/study-rooms/:roomId` | 修改信息或状态 |
| POST | `/admin/study-rooms/:roomId/time-slots` | 新增开放时段 |
| PATCH | `/admin/time-slots/:slotId` | 修改或启停时段 |
| POST | `/admin/study-rooms/:roomId/seats` | 批量新增座位 |
| PATCH | `/admin/seats/:seatId` | 修改座位 |

新增自习室默认 `status=closed`，配置至少一个有效时段和座位后才允许切换为 `open`。切换为 `open` 前检查：

- 至少有一个 `active` 时段。
- 至少有一个 `available` 座位。
- 网格尺寸能容纳全部座位坐标。
- 没有坐标冲突或重复编号。

批量新增座位请求：

```json
{
  "prefix": "A",
  "rows": 4,
  "columns": 6,
  "startRow": 1,
  "startColumn": 1,
  "skip": [
    { "row": 2, "column": 3 }
  ]
}
```

服务端生成座位编号前必须定义固定策略，例如按行使用 `A-01`、`A-02`。编号生成、坐标冲突检查和插入应在同一事务中完成；部分失败时整体回滚。

## 6. 业务规则

### 6.1 开放时段

- 新增或修改时段时检查 `start_time < end_time`。
- 不接受跨午夜时段；如需跨日，拆成两个配置。
- 同一自习室有效时段不能重叠。
- 已有预约引用的时段不允许物理删除；可改为 `inactive`。
- 修改时段的开始或结束时间可能影响未来预约，默认禁止直接修改有未来预约的时段；应新建时段并停用旧时段。
- 预约模块使用预约表中的时间快照，因此历史记录不会因时段停用而改变。

### 6.2 座位状态

- `available`：可创建新预约。
- `maintenance`：暂不可预约，需填写维修说明。
- `disabled`：长期停用，仍需保留历史预约关联。
- 将座位改为维修或停用时，不自动取消已有预约；管理员须通过预约管理处理，并记录原因。
- 座位编号和行列坐标的修改要避免影响已完成的记录展示；若业务必须修改，应保留可追溯审计。

### 6.3 网格布局

- 行列号从 1 开始，必须位于 `1..grid_rows` 和 `1..grid_columns`。
- 减少网格尺寸前检查是否有座位超出范围。
- 未被占用的网格单元用于渲染过道，不代表座位。
- 第一版不提供拖拽布局；批量生成后再用编辑表单微调坐标。

## 7. 前端交互

### 7.1 首页 `/home`

- 自习室卡片展示名称、位置、开放状态和静态可预约座位数。
- 用户同时选择日期和时段后，使用 `date`、`slotId` 刷新列表并展示动态可用座位数。
- 支持关键字搜索，条件变化时取消上一次未完成的请求。
- 空结果显示“暂无符合条件的自习室”，请求失败显示重试按钮。

### 7.2 自习室详情 `/study-rooms/:id`

- 顶部显示基础信息。
- 日期选择范围为今天到系统允许的最晚日期。
- 时段以按钮组展示，过去时段的按钮禁用。
- 座位图与图例同时显示：空闲、已预约、维修、停用。
- 座位不可用时不能点击提交；右侧或底部展示选中的座位摘要。
- 点击“立即预约”进入预约确认流程，最终结果以创建预约接口为准。

### 7.3 后台自习室管理

- 列表支持状态筛选和关键词查询。
- 编辑页分为基本信息、开放时段和座位管理三个区域。
- 危险状态切换需要二次确认，展示对现有预约的可能影响。
- 批量新增座位需要先预览生成数量和编号示例，再提交。

## 8. 异常与并发

| 场景 | 处理 |
| --- | --- |
| 查询不存在的自习室 | `404 NOT_FOUND` |
| 时段不属于该自习室 | `VALIDATION_ERROR` |
| 日期格式错误或超出可预约范围 | `VALIDATION_ERROR` |
| 时段已停用 | 返回不可用，不显示为可预约选项 |
| 座位在查询后刚被预约 | 创建接口返回 `409 CONFLICT`，前端刷新座位图 |
| 批量座位与已有编号冲突 | 整体回滚并返回冲突编号摘要 |
| 把已关闭自习室改为开放但无座位 | `CONFLICT` |

座位可用性查询不开启长事务。真正的并发约束由预约模块的座位锁定和唯一索引负责。

管理员修改自习室状态、时段或座位状态时必须开启写事务，并按“自习室 -> 时段 -> 座位”顺序操作。预约事务会持有自习室和时段的共享锁、座位的排他锁，资源修改必须等到相应预约事务提交后再继续，避免预约在“资源校验通过、记录尚未插入”的窗口内被关闭或改为维修。

## 9. 测试用例

1. 公开列表只返回允许展示的自习室。
2. 管理员可创建自习室、时段和座位。
3. 同一自习室重复座位编号被拒绝。
4. 行列坐标重复被拒绝。
5. 时段开始时间晚于结束时间被拒绝。
6. 同房间两个重叠时段被拒绝，边界相邻时段被允许。
7. 不同日期、时段下同一座位的动态状态不同。
8. 维修和停用座位始终不可预约。
9. 自习室关闭后全部座位标记为不可用。
10. 批量新增座位部分失败时无部分数据写入。
11. 学生调用管理员维护接口返回 403。
12. 座位图在无数据、接口失败和日期切换时状态正确。
13. 未选择日期和时段时不把静态可预约数误展示为动态可用数。
14. 关闭自习室与创建预约并发时，提交后预约状态和资源状态保持一致。
